ECC UX/UI 팀 10주차 스터디. 범위는 『UX·UI 디자인 교과서』 3부 5장 'UI 디자인'(343~371쪽)과 8장 '사용성 테스트'(403~436쪽)다. 11월 22일까지가 10주차 기간이었다.

지난주 4장에서 워크플로와 정보 구조를 읽었고 이번 주는 5장으로 이어진다. 6장과 7장을 건너뛰고 8장을 먼저 읽는 순서인데, 두 장을 나란히 놓으면 한쪽은 UI를 무엇으로 구성하는지를, 다른 쪽은 만든 UI를 어떻게 평가하는지를 다룬다.

| 구분 | 5장 UI 디자인 | 8장 사용성 테스트 |
| --- | --- | --- |
| 쪽 | 343~371 | 403~436 |
| 절 | UI 개념 모델, 인터랙션 디자인의 원칙, 입출력과 디바이스, UI 디자인 요소, UX 라이팅 | 특징, 조건, 다양한 평가 방법, 유형, 진행 방법, 태스크와 평가 기준, 참가자 모집과 진행 |
| 성격 | 인터페이스 유형, 원칙, 요소, 문구 | 조건, 방법, 절차, 측정 |

두 장은 같은 원칙을 공유한다. 5장의 인터랙션 원칙인 일관성, 피드백, 사용자 제어와 UX 라이팅의 명확한 오류 메시지, 도움말은 8장에 나오는 닐슨의 10가지 휴리스틱에 그대로 들어 있다. 만드는 기준이 평가 기준으로 다시 쓰인다.

## 3부 5장. UI 디자인

UI는 물리적, 시각적, 청각적, 촉각적 요소가 통합된다. 그래서 그래픽 UI뿐 아니라 물리적 UI, 음성 UI, 제스처 UI, 터치 UI, 몰입형 UI를 이해해야 한다는 것이 장 도입의 요지다.

### UI 개념 모델

![인터페이스 유형과 관계]({{ '/assets/images/club-ecc-ux-ui/ui-concept-model.svg' | relative_url }})

그림은 교재 그림 3.30을 다시 그린 것이다. 사용자 인터페이스는 크게 정보 콘텐츠 디자인과 전통적인 제품 디자인으로 구분되고, 이것들이 물리적, 그래픽, 청각적 UI와 연결된다. 점선 위쪽의 PUI, GUI, AUI가 표층이고, 아래쪽 꼭짓점의 정보 구조와 워크플로가 심층이다. 지난주에 읽은 4장의 내용이 이 그림에서는 맨 아래에 놓인다.

| 구분 | PUI (물리적) | GUI (그래픽) | AUI (청각적) |
| --- | --- | --- | --- |
| 연결 | 전통적인 제품 디자인 | 정보 콘텐츠 디자인 | 음성 및 청각 기반 상호작용 |
| 포함 요소 | 폼팩터, 어포던스, 인간공학, 크기, 버튼·다이얼 같은 제어장치, 진동 같은 촉각 인터페이스 | 아이콘, 메뉴, 테마, 메타포 | 음성 및 사운드 디자인, 음성 사용자 경험(VUX), 대화형 UI, 채팅 |
| 특징 | 사용자가 물리적으로 상호작용하는 요소 | 화면상의 그래픽 요소. 시각적 일관성을 유지하는 데 중요하다 | 점점 더 중요해지는 분야 |

교재는 이어서 UI의 종류를 하나씩 설명한다.

| UI | 정의 | 대표 예 |
| --- | --- | --- |
| 물리적 UI | 제품 디자인과 UX 디자인의 접점에 있는 디자인 요소 | 버튼, 슬라이더, 조그셔틀, 스티어링 휠, 키보드 |
| 음성 UI | 음성 명령으로 시스템과 상호작용한다 | 아마존 알렉사, 구글 어시스턴트, 삼성 빅스비, 애플 시리 |
| 제스처 UI | 터치스크린, 터치패드, 모션 센서로 손과 몸의 움직임을 통해 상호작용한다 | 게임, VR, AR, 대화형 디스플레이 |
| 터치 UI | 화면을 터치해 직접 상호작용한다 | 스마트폰, 태블릿, ATM, 키오스크 |
| 몰입형 UI | 앞으로 많이 사용될 인터페이스 | VR, AR, MR, XR, SR, BCI |

**물리적 UI.** 폼팩터는 제품의 물리적 형태와 크기이고 사용자 경험에 직접 영향을 미친다. 폴더블폰의 폼팩터는 화면의 확장성과 휴대성을 동시에 제공하고, 노트북과 태블릿PC는 이동성과 사용 편의성을, 휴대전화는 손쉬운 휴대성과 직관적인 인터페이스를 제공한다.

**음성 UI.** 손을 쓸 수 없거나 시각적 접근이 어려운 상황에서 유용하다. 기기는 마이크로 환경을 지속적으로 모니터링하다가, 상호작용을 활성화하는 단서인 음성 트리거(Voice Command Trigger)를 받으면 깨어난다. 'Hey Siri'나 'Ok Google' 같은 사전 정의된 단어를 핫워드(Hot Word) 또는 깨우기 단어(Wake-up Word)라고 한다. 핫워드를 쓰면 상호작용을 시작할 때까지 장치를 대기 상태로 둘 수 있어서 리소스를 절약한다. 운전, 요리, 장애인 지원, 현장 작업처럼 장치와 물리적으로 상호작용하기 어려운 상황에서 특히 유용하다.

**터치 UI.** 손은 신체에서 신경학적으로 가장 민감하고 운동 제어가 유리한 부위이고, 손가락 끝은 신경 말단 밀도가 높다. 그래서 터치 인터페이스는 직관적이고 학습이 쉽다.

| 비교 | 정전식 터치스크린 | 감압식 터치스크린 |
| --- | --- | --- |
| 원리 | 액정 위에 전류가 흐르고, 손 같은 전도체가 닿으면 전류가 멈추며 위치를 인식한다 | 누르는 힘을 감지해 위치를 인식한다 |
| 반응 | 빠르고 오작동이 적다. 멀티터치를 지원한다 | 느리고 멀티터치가 제한적이다 |
| 입력 도구 | 손. 장갑을 끼면 터치가 안 될 수 있다 | 비도체도 된다. 펜, 장갑 낀 손 |
| 단점 | 소비 전력이 크다 | 가벼운 터치에 민감하지 않다 |
| 쓰임 | 스마트폰, 태블릿 | 확실한 터치가 필요한 키오스크, ATM |

멀티터치 제스처는 여섯 가지가 나온다. 탭(한 번 가볍게 누름), 더블 탭(같은 위치를 빠르게 두 번), 플릭(빠르게 훑어냄), 드래그(선택한 항목을 이동), 핀치 인·핀치 아웃(두 손가락을 벌리거나 오므림), 로테이트(두 손가락을 대고 원형으로 움직임)다.

**몰입형 UI.**

| 인터페이스 | 정의 |
| --- | --- |
| VR (가상현실) | 사용자를 가상 환경에 완전히 몰입시킨다 |
| AR (증강현실) | 디지털 콘텐츠를 현실 세계에 오버랩한다 |
| MR (혼합현실) | AR이 고도화된 것. 시각·청각 외에 촉각·후각·미각을 사용하는 것을 MR이라 부르기도 한다 |
| XR (확장현실) | VR, AR, MR을 포함한 모든 몰입형 기술을 포괄하는 용어 |
| SR (대체현실) | 실제 요소와 가상 요소를 대체해서 일부가 가상이더라도 실제처럼 인식하는 하이브리드 경험 |
| BCI (뇌 컴퓨터 인터페이스) | 뇌의 전기 신호를 감지해 시스템을 직접 제어한다 |

각각 뚜렷한 장점과 한계가 있으므로 상황과 사용자 요구에 맞는 방식을 찾으려면 차이를 이해해야 한다고 교재는 정리한다.

### 인터랙션 디자인의 원칙

인터랙션 디자인은 사용자와 시스템 간의 상호작용을 설계하는 과정이다.

| 원칙 | 정의 | 교재 예 |
| --- | --- | --- |
| 일관성(Consistency) | 인터페이스 전반에 걸쳐 동일한 패턴과 규칙을 유지한다. 가장 중요한 원칙의 하나 | 대부분의 웹사이트에서 '로그인' 버튼은 오른쪽 상단에 있다 |
| 피드백(Feedback) | 현재 상태나 작업 결과를 즉각적으로 알려 준다 | 버튼을 눌렀을 때 색상 변화, 애니메이션, 사운드. 모바일에서는 진동과 시각적 변화 |
| 유연성(Flexibility) | 다양한 사용자 요구와 상황에 맞게 인터페이스가 적응한다 | 단축키를 쓰는 고급 사용자와 마우스를 쓰는 초보 사용자 모두에게 맞는 중복(Redundancy). 텍스트 음성 변환, 화면 확대 |
| 사용자 제어(User Control) | 시스템을 이해하고 필요에 따라 동작을 조정할 수 있다는 확신을 준다 | 실수했을 때 '되돌리기(Undo)'로 쉽게 복구한다 |

일관성은 익숙한 경험과 기대치를 반영해서, 새 기능도 기존 경험으로 적응하게 한다. 버튼을 눌렀는데 반응이 없으면 사용자는 작동하지 않는다고 생각한다. 피드백은 올바른 경로에 있다는 확신을 준다. 사용자 제어는 신뢰와 연결된다. 시스템이 의도와 다르게 작동하거나 제어를 제한하면 사용자는 신뢰를 잃는다.

### 입출력과 디바이스

입력은 사용자가 시스템에 데이터를 제공하거나 명령을 내리는 방식이고, 출력은 시스템이 사용자에게 정보를 제공하는 방식이다.

| 구분 | 종류 | UI 디자인에서 고려할 것 |
| --- | --- | --- |
| 입력 | 터치 | 요소의 크기와 간격을 적절하게 하고 멀티터치 제스처를 직관적으로 활용한다 |
| 입력 | 키보드와 마우스 | 레이아웃을 단순하고 일관되게 하고, 키보드 내비게이션과 단축키를 지원한다 |
| 입력 | 음성 | 자연어 처리 능력을 갖추고, 명령을 이해하기 쉽게 가이드를 제공한다 |
| 입력 | 스타일러스와 펜 | 필압 감지, 정확한 포인팅, 캘리브레이팅, 적절한 피드백 |
| 출력 | 화면 디스플레이 | 반응형 레이아웃을 도입하고 명확한 시각적 정보를 준다 |
| 출력 | 사운드 | 환경에 맞게 조절·소거할 수 있게 하고 중요한 알림을 놓치지 않게 한다 |
| 출력 | 햅틱 피드백 | 과도한 부담을 주지 않도록 미세 조정한다 |

디바이스는 입출력 인터페이스를 제공하는 도구다.

| 디바이스 | 특징 | UI 디자인 방향 |
| --- | --- | --- |
| 모바일 | 작은 화면, 터치 입력, 다양한 센서 | 가독성을 유지하면서 효율적인 내비게이션, 반응형 디자인 |
| 데스크톱과 노트북 | 큰 화면, 키보드·마우스, 멀티태스킹 | 계층적 메뉴와 툴바, 다양한 창 관리 |
| 웨어러블 | 매우 작은 화면, 제한된 입력, 항상 휴대 | 간결하고 직관적으로. 간단한 제스처나 음성 명령으로 작동 |
| 스마트 스피커 | 음성 입력 중심, 화면이 없거나 제한적 | 자연어 처리와 직관적 피드백 |
| IoT 디바이스 | 인터넷에 연결되어 데이터를 수집·전송·처리하는 물리적 객체. 시각적 인터페이스가 없기도 하다 | 디바이스 특성과 사용 맥락을 깊이 이해한다 |

교재 그림 3.31은 이 관계를 표로 보여 준다. 디바이스는 디스플레이, 스피커, 진동으로 출력하고 사람은 눈, 귀, 피부로 받는다. 반대로 사람의 행동과 표정, 목소리, 터치는 디바이스의 카메라, 마이크와 센서, 버튼과 다이얼로 들어간다.

입력에는 사용자가 의도하지 않은 것도 있다. 카메라, 마이크, GPS, 무선통신망, 전력 사용량 같은 센서가 모으는 데이터다. 스마트폰은 위치에 따라 경고 메시지를 보내거나 분실했을 때 위치를 파악한다. 기기가 너무 뜨거우면 사용을 중지시켜 보호한다. 공장의 기기는 전력 사용량이 지나치게 높거나 낮은지, 평소와 다른 소리가 나는지를 사전 데이터로 파악해서 선제적으로 정비한다.

### UI 디자인 요소

제시 제임스 개럿(Jesse James Garrett)은 『사용자 경험의 요소』에서 UX 요소 모델을 다섯 단계로 설명했다.

| 단계 | 결정·설계하는 것 | UI 디자인의 범위 |
| --- | --- | --- |
| 전략적 목표(Strategy) | 제품이나 서비스의 목표와 비전 | |
| 범위(Scope) | 기능, 콘텐츠, 기술적 제약 | |
| 구조(Structure) | 정보 구조, 내비게이션, 사이트 맵 | 해당 |
| 프레임(Skeleton) | 레이아웃, 인터페이스 요소, 상호작용 디자인 | 해당 |
| 표면(Surface) | 색상, 글꼴, 그래픽 디자인 등 시각적 요소 | 해당 |

UI 디자인에서 다루는 범위는 구조, 프레임, 표면이다. 그 안의 디자인 요소로 교재는 열두 가지를 든다.

| # | 요소 | 내용 |
| --- | --- | --- |
| 1 | 색상 | 가장 강력한 시각적 요소 중 하나. 빨간색은 주의·경고, 파란색은 신뢰·안정감, 회색은 비활성화. 색상 대비는 접근성과 연결된다 |
| 2 | 글꼴 | 세리프체는 클래식하고 권위적, 산세리프체는 현대적이고 깔끔하다. 헤드라인과 본문에 다른 크기와 굵기를 써서 글꼴의 계층 구조를 만든다 |
| 3 | 레이아웃 | 그리드 시스템은 일관된 레이아웃을 주고 반응형 디자인에 필수다 |
| 4 | 간격과 여백 | 요소 간의 관계를 정의한다. 적절한 간격은 클릭 오류를 줄인다 |
| 5 | 이미지와 비주얼 요소 | 전자상거래의 제품 이미지는 구매 결정을 돕는다. 일관성, 해상도, 로딩 시간을 고려한다 |
| 6 | 모션과 애니메이션 | 상태 변화를 전달하고 피드백을 준다. 지나치지 않게 신중하게 쓴다 |
| 7 | 피드백과 상태 표시 | 로딩 스피너, 알림 메시지, 진행 바 같은 상태 표시기 |
| 8 | 사운드와 햅틱 피드백 | 시각적 피드백과 함께 다감각적 경험을 준다. 모바일과 웨어러블에서 효과적이다 |
| 9 | 내비게이션 요소 | 메뉴, 링크, 버튼. 주요 메뉴는 주로 상단에 고정된다 |
| 10 | 정보 디자인 | 표, 그래프, 인포그래픽으로 복잡한 정보를 이해하기 쉽게 표현한다 |
| 11 | 인간공학 | 터치 대상은 정확히 탭할 수 있는 크기로, 한 손 사용 시 엄지손가락이 닿는 위치에 둔다 |
| 12 | 어포던스 | 행동을 유도하는 요소. 사용 방법을 제안하고 암시한다 |

어포던스(Affordance)는 심리학자 제임스 깁슨(James Gibson)이 소개했고 도널드 노먼(Donald Norman)의 디자인 맥락에서 대중화되었다. 명시적인 지침 없이도 상호작용 방법을 이해하게 한다.

| 유형 | 내용 | 교재 예 |
| --- | --- | --- |
| 물리적 어포던스 | 인터페이스를 직관적으로 만들어 인지 부하를 줄인다 | 누를 수 있을 것처럼 보이는 버튼, 드래그할 수 있을 것처럼 보이는 슬라이더 |
| 지각적 어포던스 | 사용자의 인식과 경험에 따라 달라진다 | 쓰레기통 아이콘은 파일을 삭제하는 공간. 글자나 아이콘이 붙은 도형의 그림자는 누르면 무언가 일어난다는 인식 |
| 문화 관습적 어포던스 | 시간이 지나며 생긴 패턴, 문화에 따른 관습 | 재생 버튼 기호, 햄버거 메뉴 아이콘 |

교재는 도입 문장에서 두 번째 유형을 '인지적 어포던스'라고 부르고 항목 설명에서는 '지각적 어포던스'라고 쓴다. 표는 항목 설명의 표기를 따랐다.

### UX 라이팅

UX 라이팅(User Experience Writing)은 사용자와 소통하는 텍스트를 작성하는 과정이다. 버튼 레이블, 메뉴, 오류 메시지, 도움말 텍스트, 매뉴얼이 범위에 들어간다. 지난주 4장의 메뉴 설계 8단계에서 네 번째 단계가 '라벨링과 UX 라이팅'이었다.

역할은 일곱 가지다.

| # | 역할 | 내용 |
| --- | --- | --- |
| 1 | 명확성(Clarity) 확보 | 필요한 정보를 빠르게 이해하게 한다. 단계별 지침, 명확한 오류 메시지와 해결 방법 |
| 2 | 일관성(Consistency) 제공 | 동일한 용어와 톤을 유지한다. 브랜드의 목소리를 강화한다 |
| 3 | 친근감(Empathy) 조성 | 전문용어 대신 쉬운 언어, 격려하는 톤 |
| 4 | 효율성(Efficiency) 확보 | 복잡한 절차를 간단한 단계로 나누고 핵심 정보만 전한다 |
| 5 | 사용자 참여(Engagement) 유도 | 진행 상황의 게임화, 작업 수행을 칭찬하는 메시지 |
| 6 | 접근성(Accessibility) 확보 | 화면 리더가 잘 인식하도록 텍스트를 작성한다 |
| 7 | 피드백(Feedback) 제공 | 폼 제출 시 "성공적으로 제출되었습니다!" |

교재는 나쁜 사례와 좋은 사례를 열두 범주로 나란히 싣는다. 범주마다 하나씩 옮겼다.

| 범주 | 나쁜 사례 | 좋은 사례 |
| --- | --- | --- |
| 오류 메시지와 차선책 | "오류 404" | "페이지를 찾을 수 없습니다. URL을 확인하거나 홈페이지로 돌아가세요." |
| 입력 가이드라인 | "날짜를 입력하세요." | "생년월일을 입력하세요. (예: YYMMDD)" |
| 버튼 레이블 | "제출" 혹은 "확인" | "계정 만들기" 혹은 "무료 평가판 시작" |
| 확인 메시지 | "확인" | "파일을 삭제하시겠습니까? 이 작업은 취소할 수 없습니다." |
| 작업 단계 안내 | "다음" | "개인정보 입력하기 (2/5)" |
| 작업에 대한 피드백 | "저장됨" | "설정이 저장되었습니다." |
| 내비게이션 레이블 | "설정" | "계정 설정" 혹은 "프로필 및 환경설정" |
| 정보 제공 문구 | "데이터 동기화" | "2분 전에 파일이 동기화되었습니다." |
| 법률 및 보안 고지 | "동의" | "'동의'를 클릭하면 당사에서 귀하의 데이터를 처리하는 데 동의하는 것입니다. 개인정보 처리방침은 '여기'를 눌러 주세요." |
| 하드웨어 매뉴얼 | "전원을 켜세요." | "파워 버튼을 3초간 눌러 전원을 켜세요." |
| 폼과 입력 필드 | "비밀번호" | "비밀번호를 입력하세요. (8자 이상, 숫자와 특수문자 포함)" |
| 안내 메시지 | "로딩 중" | "데이터를 불러오는 중입니다. 약 1-2분 소요될 예정입니다." |

표를 세로로 읽으면 공통점이 보인다. 나쁜 사례는 한 단어나 코드, 기호다. 좋은 사례는 무엇을 하는지, 어떤 결과가 생기는지, 어떻게 해결하는지, 얼마나 걸리는지를 문장으로 말한다. 특히 "취소를 누르면 입력한 내용이 삭제됩니다."처럼 부정적인 결과는 꼭 명시하라고 교재는 덧붙인다.

## 3부 8장. 사용성 테스트

사용성 테스트는 프로토타이핑으로 만든 결과물을 평가하고 측정하는 방법이고 사용자 테스트라고도 한다. 교재는 사용성 테스트가 UX·UI 디자인에서 가장 효과적인 방법인 만큼 다른 방법에 비해 절차적으로 준비할 것이 많고, 명시지 형태로 학습할 내용이 많다고 예고한다.

### 사용성 테스트의 특징

사용성 테스트는 UX·UI 디자인에서 가장 연구가 오래된 분야다.

| 연도 | 사건 |
| --- | --- |
| 1980년대 | 퍼스널 컴퓨터 시장이 등장하고 업무용 소프트웨어가 확산되었다 |
| 1986 | 도널드 노먼 『User Centered System Design』 |
| 1988 | 도널드 노먼 『The Design of Everyday Things』(출간 당시 제목은 『The Psychology of Everyday Things』) |
| 1990년대 초 | 사용성 테스트가 본격적으로 등장했다. UX 디자인이라는 용어보다 먼저다 |
| 1993 | 제이콥 닐슨 『Usability Engineering』 |

UX 디자인 분야 전반이 마케팅 같은 유연한 학문(Soft Science)의 영향을 받아 정성적인 데 비해, 사용성 테스트는 실험심리학 같은 엄밀한 학문(Hard Science)의 영향을 받아 정량적이다. UI 디자인이 결과물을 만드는 실천이라면 사용성 테스트는 그 결과물을 평가하는 리포팅 작업에 가깝다.

프로세스상 맨 뒤에 있지만 항상 마지막에 할 필요는 없다. 약간 바꾸면 리서치 초기에 니즈 탐색용으로, 디벨롭 초기에 대안 탐색 수단으로 쓸 수 있다. 교재는 사용성 테스트를 프로젝트의 마지막 단계로 고정해서 보지 말라고 당부한다.

오래된 분야라서 오래된 기준이 남아 있다는 점도 짚는다. 닐슨 휴리스틱의 초점은 시스템이 헷갈리지 않는지, 오류를 일으키지 않는지에 있다. 사용의 재미, 사람들 사이의 사회적 상호작용, 문화적 이슈는 다루지 않는다. '수행 시간이 짧을수록 좋다'는 기준으로는 게임 경험을 파악하기 어렵다. 게임은 빨리 깰 수 있다고 좋은 것이 아니기 때문이다.

**사용성의 정의.**

| 정의 | 사용성의 구성 |
| --- | --- |
| ISO-9241-11 | 효과성, 효율성, 만족도의 총체 |
| 제이콥 닐슨 (ISO 이전) | 학습 용이성, 사용 효율성, 기억 용이성, 오류 최소화, 주관적 만족 |

ISO는 닐슨의 정의에서 인지적 이슈를 덜어내고 중첩되는 영역을 줄였다. 사용성 테스트는 유용성, 심미성, 시장성, 사회적 수용성 평가와 다르다. 가장 큰 관심은 사용자가 시스템을 무리 없이 사용할 수 있는가에 있다.

**용어.** 테스트는 평가보다 가볍고 실험보다 덜 엄밀하다. 그래서 'Usability Test'는 '사용성 평가'보다 '사용성 테스트'로 쓰는 것이 바람직하다. '사용자 테스트'라는 말에 대해서는 정통적 견해가 있다. 사용자'가' 평가하는 것이지 사용자'를' 평가하는 것이 아니므로 부적합하다는 것이다. 다만 오래전부터 구분 없이 쓰여 왔고 교재도 둘을 명확히 구분하지 않는다.

**왜 하는가.** 좋은 디자인 솔루션을 찾는 것이 대표적인 목적이다. 가장 뚜렷한 장점은 수치적인 입증이 가능하다는 것이다. 닐슨은 『Return on Investment for Usability』(2003)에서 863개 프로젝트의 데이터를 근거로 프로젝트 예산의 10%를 사용성 테스트에 써야 한다고 주장했다. 사용성 테스트 비용이 8-13%였다는 데서 귀납적으로 나온 수치다. 예산이 10배인 프로젝트라면 사용성 지출은 4배가 필요해서 규모에 따라 선형적으로 늘지는 않는다.

| 웹 프로젝트 개선 항목 | 개선율 |
| --- | --- |
| 판매와 전환율 | 평균 100% |
| 트래픽과 방문자 수 | 150% |
| 사용자 성능과 생산성 | 161% |
| 특정 기능의 사용 | 202% |

전환율처럼 유용성에 가까운 항목보다 특정 기능의 사용처럼 사용성에 가까운 항목일수록 개선 정도가 높다. 사용성 테스트는 좁고 명확한 문제에 더 효과적인 방법이라는 뜻이다.

**분류 기준.** 교재 그림 3.44는 사용성 테스트를 여섯 기준으로 나눈다.

| 기준 | 한쪽 | 다른 쪽 |
| --- | --- | --- |
| 누가(By whom) | 전문가(휴리스틱 평가) | 사용자 |
| 데이터(Data) | 질적 평가: 과정의 느낌, 태도 | 양적 평가: 태스크 성공 여부, 반응 시간 |
| 평가의 초점 | 과정 평가 | 수행성(결과) 중심 |
| 태스크(Task) | 수반하지 않음(관찰, 탐색) | 수반함(측정, 실증) |
| 시기(Fidelity) | 초기(LF 프로토타입) | 후기(HF 프로토타입) |
| 장소(Where) | 현장: 자연스러운 조건 | 실험실: 통제된 조건 |

각각 장단점이 있지만 연구가 심화되면서 합의가 형성되어 있다. 전문가 평가보다 사용자 참여가, 실험실보다 현장이, 후기에만 하는 것보다 초기부터 반복하는 것이 바람직하다.

### 사용성 테스트의 조건

닐슨은 『Usability Engineering』에서 사용성 테스트의 정신과 태도를 열 가지 슬로건으로 정리했다.

| # | 슬로건 | 교재 해설 |
| --- | --- | --- |
| 1 | 최고의 추정이라 하더라도 그것으로 충분하지는 않다 | 추측하지 말고 측정하라 |
| 2 | 사용자는 항상 옳다 | 사용자 의견은 원칙적으로 옳지만 |
| 3 | 사용자가 항상 옳은 것은 아니다 | 부분적, 예외적으로는 틀릴 수 있다 |
| 4 | 사용자는 디자이너가 아니다 | 만들 솔루션을 사용자에게 직접 묻거나 기대하지 말라 |
| 5 | 디자이너는 사용자가 아니다 | '나도 사용자다'라는 생각을 버리고 다수 사용자의 의견을 들어라 |
| 6 | 부사장은 사용자가 아니다 | 의사 결정권자라도 그들의 의견에 좌우되지 않아야 한다. 실제로 지키기 가장 어렵다 |
| 7 | 적을수록 더 좋다 | 인터페이스의 심플함 |
| 8 | 세부 사항이 중요하다 | |
| 9 | 도움말은 도움이 되지 않는다 | 도움말이 필요하지 않을 정도로 직관적인 인터페이스가 중요하다 |
| 10 | 사용성 공학은 프로세스이다 | 사용성 개선은 지속적이고 체계적인 과정이다 |

4번과 5번은 1주차 인터뷰에서 읽은 '말과 행동은 다르다'와 같은 방향이다. 교재 본문은 "슬로건 3과 4는 모순되어 보인다"고 쓰지만 이어지는 설명은 사용자 의견이 옳기도 하고 틀리기도 하다는 내용이어서, 실제로 가리키는 쌍은 2번과 3번이다.

**참가자 수.** 정량 연구를 기준으로 하면 최소 표본 수는 30명 정도다. 그런데 닐슨은 참가자가 다섯 명이면 사용성 문제의 80% 이상을 찾아낸다고 주장했다.

![사용성 테스트의 참가자 수와 발견되는 사용성 문제]({{ '/assets/images/club-ecc-ux-ui/ut-participants-curve.svg' | relative_url }})

교재 그림 3.45의 모양을 따라 그린 것이고, 5명 지점의 표시는 본문의 설명을 옮겨 넣은 것이다. 곡선은 초반에 급격히 오르고 그 뒤로는 100%에 완만하게 수렴한다. 그래서 결론이 얻어졌다면 참가자를 늘리기보다 새 프로토타입을 만들어 다음 버전을 테스트하는 편이 낫다. 투자 의사 결정처럼 명확한 근거가 필요하거나 AB 테스트에서 선호도가 뚜렷이 드러나지 않을 때는 참가자를 더 확보한다.

**사용성 테스트 룸(UT Room).** 실험실에는 모더레이터(진행자), 참가자, 프로토타입, 벽 모서리의 CCTV가 있다. 관찰실과의 경계는 단방향 거울(One-way Mirror)이다. 관찰실에서는 실험실이 보이지만 실험실에서는 검은 유리벽만 보인다. 관찰실에는 CCTV 화면을 모아 보여 주는 모니터와 진행자에게 지시하는 마이크가 있다.

UT 룸의 필요성은 예전만큼 강조되지 않는다. 이유는 세 가지다.

| 이유 | 내용 |
| --- | --- |
| 현장의 맥락 결여 | 거실 소파에서 쓰는 스마트폰 앱, 버스에서 듣는 무선 이어폰, 어두운 골목에서 QR로 대여하는 공공 자전거 앱을 실험실에서 재현하기 어렵다 |
| 심리적 부담 | CCTV와 단방향 거울 때문에 참가자는 취조실에 앉은 마음이 된다. 조작 능력이 아니라 UI를 평가한다고 말해도 위축된다 |
| 구축 비용 | 만만치 않아서 수요가 확연히 줄었다 |

그래도 UT 룸 구성에서 고려되는 실험 통제와 계획은 여전히 잘 이해해야 한다.

**임장감.** 테스트 환경은 실제 상황을 완벽히 구현할 필요가 없다. 간단한 설정과 장치만으로도 임장감을 줄 수 있다.

| 사례 | 설정 |
| --- | --- |
| 자동차 내비게이션 | 사무용 의자, 종이 운전대, 화이트보드에 그린 도로. 이런 설정조차 없으면 참가자는 전방을 주시하며 힐긋 보는 것이 아니라 스마트폰을 보듯 무릎 위에 올려놓고 쓴다 |
| 패러글라이딩 조작 인터페이스 | 흔들리는 의자, 부채질로 만든 바람, 눈앞 TV의 활강 영상 |
| 세탁기와 비데의 컨트롤 패널 | 세탁기 패널을 그냥 주면 태블릿PC를 쓰는 자세가 된다. 비데 패널은 의자에 부착해서 고개를 돌려 봐야 하는 시선과 손의 각도를 실제와 같게 한다 |

### 다양한 사용성 평가 방법

실제 사용자에게 태스크를 주는 전형적인 방식 외에도 여러 평가 방법이 있다.

**휴리스틱 평가.** 휴리스틱은 우리말로 '어림값'이고, 정확한 계산이나 측정 없이 직관적으로 판단하는 예측이다. 휴리스틱 평가는 사용성 전문가가 축적된 경험과 지식으로 시스템의 사용성을 예측하고 판단하는 것이어서 전문가 평가(Expert Review)라고도 한다. 전문가가 태스크를 수행하지 않고 마음속으로 사용 과정을 절차적으로 점검하는 인지적 시찰법(Cognitive Walkthrough)도 비슷한 방법이다.

| 구분 | 내용 |
| --- | --- |
| 장점 | 준비에 노력과 비용이 덜 들고 빠르다. 시나리오 작성, 참가자 섭외가 없어진다 |
| 장점 | 통찰점을 해석할 필요가 없고 해결책이 같이 제공된다 |
| 단점 | 평가자가 실제 사용자가 아니다. 50대 남성 전문가가 20대 여성 대상 제품을 평가하면 이해가 충분하지 않다 |
| 단점 | 인지적 이슈에는 통찰력이 뛰어나지만 라이프스타일이나 취향의 문제는 판단하기 어렵다 |
| 단점 | 전문가의 역량과 주관에 따라 해석이 크게 달라진다 |

두 번째 장점의 예가 구체적이다. 일반 참가자가 난감한 표정으로 머뭇거릴 때, 어떤 버튼을 누를지 몰라서인지(인지적 사용성의 문제) 서비스가 마음에 안 들어서인지(유용성의 문제) 알기 어렵다. 전문가는 '이 화면에서 모달뷰가 나와서 혼동이 생긴다'는 진단과 '모달뷰 대신 전체 화면으로 뜨는 리스트 메뉴로 교체하라'는 해결책을 같이 준다.

제이콥 닐슨의 10가지 사용성 휴리스틱(1994)을 교재는 네 그룹으로 재정렬한다.

| 그룹 | 휴리스틱 |
| --- | --- |
| 시스템에 대한 사용자의 인식 | 시스템 상태를 가시화하라(Visibility), 시스템과 실세계를 연결지어라(Mapping), 회상보다 재인하게 하라(Recognition) |
| 시스템의 자유도 | 사용자 통제권과 자유를 제공하라(Freedom), 사용상의 유연성과 효율성을 높여라(Flexibility) |
| 전반적인 디자인 원칙 | 일관성과 표준을 지켜라(Consistency), 미학적이고 미니멀하게 디자인하라(Minimalism) |
| 오류 대책 | 오류를 예방하라(Error Prevention), 사용자가 오류를 인식·진단·복구할 수 있게 하라(Error Recovery), 도움말과 설명을 제공하라(Help) |

5장과 겹치는 지점이 이 표에서 보인다. 일관성과 표준, 사용자 통제권, 유연성, 상태 가시화는 인터랙션 디자인의 네 원칙과 같은 말이고, 오류 복구는 UX 라이팅 사례의 첫 범주인 오류 메시지와 차선책에, 도움말은 UX 라이팅의 범위로 꼽힌 도움말 텍스트에 이어진다. 한계도 교재가 직접 적는다. 발표된 지 오래되었고, 오류 대책은 많은 반면 와우포인트에 대한 논의는 없다. 4주차 고객 여정 지도에서 페인포인트의 반대편에 있던 그 와우포인트다.

**구글 HEART 프레임워크.** 전통적인 기준의 부족한 점을 보완하려고 구글이 개발했다. 사용성이 아니라 사용자 경험을 측정하고 개선하기 위한 것이다.

| 항목 | 측정 |
| --- | --- |
| H 행복(Happiness) | 설문을 통한 종합적 만족도, 추천 여부 |
| E 참여(Engagement) | 제품 사용 시간과 빈도 |
| A 채택(Adoption) | 서비스 가입과 가입 후 재사용 비율 |
| R 유지(Retention) | 시스템에 남아 있는 사용자 수 |
| T 태스크의 성공(Task Success) | 작업 완료까지의 시간이나 에러율 |

가운데 세 가지는 GA(Google Analytics) 같은 도구로 파악한다.

**설문 기반 평가 도구.**

| 도구 | 개발 | 구성 | 초점 |
| --- | --- | --- | --- |
| SUS (System Usability Scale) | 1980년대 DEC | 10개 문항, 5점 리커트 | 사용성 |
| QUIS | 메릴랜드대학, 1988년 | 전반적 만족도, 화면, 용어, 학습성 등. 0-9점 | 사용성 |
| SUPR-Q | | 웹사이트 특화. 사용성, 신뢰성, 외관, 충성도 | 사용성 |
| SERVQUAL | 1980년대 마케팅 연구자들 | RATER: 신뢰성, 확실성, 유형성, 공감, 반응 | 서비스 품질 |
| NASA-TLX | 1980년대 NASA | 6개 문항, 21점 리커트 | 과업 부하 |

SUPR-Q 충성도의 마지막 문항은 NPS(순추천지수) 질문과 같다. NPS는 2003년 프레데릭 라이히헬드가 제안한 것으로 추천자 비율에서 비방자 비율을 뺀 값이다. 설문 도구는 지표화되어 있어 다른 시스템과 비교하기 쉽지만, 점수가 낮거나 높게 나온 이유를 알 수 없고 개선 방향을 제시하지 못한다. 점수가 수치로 나오더라도 본질은 참가자의 주관적 인식이고, 평가자가 30명 이하라면 평균치에 지나치게 연연하지 않는 것이 좋다고 한다. 2주차에 읽은 설문과 통계의 주의점이 그대로 적용된다.

**행동 데이터 측정.** 아이트래킹은 '사용자가 주의를 기울이는 곳에 시선이 머문다'는 인지심리학적 전제에서 출발하고 히트맵과 게이즈 플롯으로 시각화한다. 클릭맵 분석은 화면 어디를 클릭했는지를 서버에 기록해 장기간 축적한 데이터로 분석한다. 아이트래킹에서 알려진 시선 패턴이 세 가지 있다.

| 패턴 | 설명 |
| --- | --- |
| F자 | 상단 정보는 왼쪽에서 오른쪽으로 꼼꼼히 보고, 아래로 갈수록 듬성듬성 건너뛴다 |
| E | 웹 하단이나 앱의 탭바 영역에서 다시 집중한다 |
| Z | 위쪽을 왼쪽에서 오른쪽으로 본 뒤 대각선으로 내려가 다시 오른쪽으로 훑는다 |

사용자는 꼼꼼히 보지 않고 스캔하는 경향이 있다. 그래서 주요 콘텐츠나 CTA(Call to Action) 버튼은 주목받는 영역을 벗어나지 않게 배치한다.

### 사용성 테스트의 유형

| 유형 | 내용 | 한계 |
| --- | --- | --- |
| 래피드 테스트·파일럿 테스트 | 페이퍼 프로토타입 같은 초기의 LF 프로토타입으로 진행한다. 초기 디자인 방향을 잡기에 적당하다 | 덜 정밀하고 탐색적이다 |
| 현장 사용성 테스트 | 사무실을 벗어나 실제 사용 상황을 구현한다 | |
| AB 테스트 | 복수의 대안을 비교한다. 인터뷰 없이 대량의 사용 데이터(Log data)로 행동을 검증한다 | 기술적 토대가 필요해서 소규모 에이전시나 개인 연구자는 하기 어렵다 |
| 위저드 오브 오즈(WoZ) | 완성되지 않은 시스템을 완성된 것처럼 믿게 만들어 진행한다 | 실제 상황이라고 믿을수록 자연스럽지만 실험 통제력을 잃을 수 있다 |

현장 테스트의 사례는 공공 자전거 대여·반납 키오스크다. 테스트 당시에는 앱이 아니라 터치형 키오스크 방식이었고, 개선안을 설치한 대형 태블릿PC를 원래 키오스크 위에 덧대고 테스트했다. 현장에서만 확인되는 요인이 있었다. 쓸 수 있는 자전거가 몇 대인지, 키오스크가 자전거와 얼마나 떨어져 있는지, 햇빛에 화면이 안 보이는지, 주변 소음, 다음 사용자가 기다려서 초조하지 않은지다.

위저드 오브 오즈는 앨런 튜링의 튜링 테스트에서 영감을 받았고 보이스 인터랙션과 챗봇에서 가장 쉽게 쓸 수 있다. 사례는 두 가지다. 홈IoT 챗봇 테스트에서는 다른 연구실의 대학원생이 챗봇 역할을 하며 채팅했고, 참가자는 테스트가 끝날 때까지 출시된 챗봇이라고 생각했다. 어린이 대상 인공지능 스피커 테스트에서는 옆에 앉은 연구자가 타이핑한 대화글을 음성 서비스가 목소리로 바꿔 들려주었다. 준비한 패턴이 아니면 타이핑하느라 약간 지체됐지만 아이들은 눈치채지 못했다.

### 사용성 테스트의 진행 방법

진행의 원칙은 두 가지다.

| 원칙 | 내용 |
| --- | --- |
| 반복(Iteration) | 한 번으로 끝내려 하지 말고 반복적으로 진행하며 단계적으로 발전시킨다. 개발 마지막 단계에서 회복할 수 없는 문제가 드러나면 고치기 어렵다. 초기부터 작은 규모의 시행착오로 위험 구역을 피해 가는 것이 현명하다 |
| 통합(Integration) | 디자인과 평가가 통합되어야 한다. 평가를 외부에 맡기면 사이클이 느려지고, 인사이트를 디자인팀에 온전히 전달하기 어렵고, 문서화에 시간과 비용이 든다 |

반복을 하려면 디자인과 평가가 통합되어 있는 편이 유리해서 두 원칙은 서로 연결된다. 오늘날에는 방법과 도구가 발달해서 디자이너나 기획자가 전문가의 도움 없이 독자적으로 진행할 수 있다.

![사용성 테스트의 절차]({{ '/assets/images/club-ecc-ux-ui/ut-procedure.svg' | relative_url }})

교재 그림 3.55를 다시 그린 것이다. 가운데 파란 묶음, 즉 현장에서 참가자와 진행하는 사전 조사·테스트 진행·사후 조사가 좁은 의미의 사용성 테스트이고, 준비와 분석까지 포함한 전체가 넓은 의미의 사용성 테스트다. 1주차 인터뷰와 2주차 관찰의 절차도 준비, 본 단계, 분석의 세 덩어리였다.

**계획 수립.** 목표를 문장으로 명확히 적는다. 목표에 따라 방법이 달라지기 때문이다. 개발 초기에 사용자 니즈에 대한 광범위한 통찰을 얻으려면 새 프로토타입 없이 기존 제품이나 와이어프레임 수준의 프로토타입으로 사용 과정을 관찰하면 된다. 이사진을 설득할 수치가 필요하면 추론통계 결론을 낼 수 있게 다수의 참가자를 섭외하고 성공 여부와 수행 시간을 명확히 계측한다. 가벼운 테스트는 하루에 본 단계를 마칠 수도 있고, 참가자를 많이 섭외하면 분석까지 3-4주가 걸린다.

**실험 설계.** 사용성 테스트는 엄밀한 실험 연구와 다르지만, 프로토타입이라는 자극을 주고 조작 과정이라는 반응을 본다는 점에서 실험이다.

| 비교 | 피험자 간 설계(Between Subject) | 피험자 내 설계(Within Subject) |
| --- | --- | --- |
| 시안 제시 | 한 명에게 하나의 디자인 시안 | 한 명에게 여러 개의 디자인 시안 |
| 특징 | 엄밀한 실험 설계에 좋다 | 참가자 섭외의 어려움을 덜어 준다. 순서 효과와 학습 효과를 상쇄해야 한다 |

같은 태스크를 반복하면 두 번째를 더 잘하게 되는 것이 순서 효과다. 역균형법(Counterbalancing Design)을 적용하거나, 실험 간격을 충분히 두거나, 망각할 만한 이벤트를 제시해서 상쇄한다.

### 태스크와 평가 기준

태스크를 주지 않는 테스트도 있지만 일반적으로는 주는 것이 바람직하다. 무엇을 알아보려는지가 명확해지기 때문이다.

태스크는 문장 형태로 제시하고, 지시에 앞서 사용자가 어떤 사람인지와 상황을 먼저 준다. 교재 예는 이렇다. '당신은 30대 초반의 전문직 여성입니다. 편집 몰에서 의상 구매를 즐기는 당신은 지금 여름휴가 때 입을 옷을 구매하려는 상황입니다. 지그재그몰에서 패션 의류를 구매하고 결제를 완료해 주세요.' 최종 목표만 제시하고 세부 목표와 조작은 참가자가 판단하게 한다. 3주차에 읽은 시나리오와 4주차의 퍼소나가 태스크 문장의 재료가 된다.

| 부적절한 태스크 | 예 | 문제 |
| --- | --- | --- |
| 모호한 태스크 | '마음껏 써 보세요.' | 평가할 수 없다 |
| 구체적인 태스크 | '세 번째 메뉴에서 (약물 확인)리스트를 고른 후 플레이 버튼을 눌러 재생시키세요.' | 조작 단위까지 지시하면 사용성을 파악할 수 없다 |

정답이 드러나지 않게 쓰는 요령도 예로 나온다. 'AM 12시에 알람을 맞춰 주세요'라고 쓰면 참가자는 'AM'과 '12'를 기계적으로 찾아 수행한다. '내일은 당신 절친의 생일입니다. 가장 먼저 축하해 줄 수 있도록 12시에 알람을 맞춰 주세요'라고 쓰면 정답인 'AM'을 쓰지 않고도 머릿속에 자정이라는 개념이 만들어진다.

> 측정할 수 없으면 평가하기 어렵고, 측정할 수 있으면 평가할 수 있다.

그래서 측정 기준을 미리 정의한다. 태스크 성공은 '진행자 도움 없이 3분 이내에 달성', 수행 시간은 '첫 번째 마우스 클릭부터 참가자 스스로 종료 버튼을 누를 때까지'처럼 적는다.

| 데이터 유형 | 항목 | 측정 방법 |
| --- | --- | --- |
| 태스크 수행 데이터 (정량) | 성공 실패 여부, 수행 시간, 에러 횟수 | 사용성 테스트 기록 |
| | 총 버튼 조작 횟수, 인터랙션 패턴 | 데이터 로깅 |
| 생리 데이터 (정량) | 마우스트래킹, 아이트래킹, 발한·근전도·뇌파 | 데이터 로깅 |
| 주관적 데이터 (정성) | 얼굴 표정, 손동작, 말 | 관찰 |
| | 만족도, 인지된 난이도, 지속 사용·구매 의도 | 설문 조사(리커트 척도) |

교재 표 3.4를 줄인 것이다. 위쪽으로 갈수록 태스크라는 좁고 명확한 인지심리학적 이슈와, 아래쪽으로 갈수록 구매 같은 마케팅 이슈와 관련된다. ISO의 사용성 정의와 가장 긴밀하게 연결되는 것은 세 항목이다. 성공 실패 여부는 효과성(명목 데이터), 수행 시간은 효율성(비율 데이터), 만족도는 만족도(등간 데이터)에 대응한다. 2주차에 정리한 데이터의 척도가 여기서 다시 쓰인다.

**태스크와 프로토타입.** 프로토타입의 완성도에 따라 테스트의 진행 정도가 결정된다.

![태스크와 프로토타입의 관계]({{ '/assets/images/club-ecc-ux-ui/ut-task-prototype.svg' | relative_url }})

교재 그림 3.58의 사분면이다. 세로축이 프로토타입의 완성도, 가로축이 태스크의 구체성이다. 초기에는 왼쪽의 두 칸을 쓴다. 이미 출시된 기성 제품은 모든 기능이 작동하므로 포괄적인 태스크에도 대응하고, 페이퍼 프로토타입 같은 LF 프로토타입은 넓게 보여 주는 수평적 프로토타입이기 쉽다. 프로젝트가 진행되면 오른쪽 위로 간다. 제한된 범위에서 완벽히 작동하는 HF 프로토타입이고, 수직적 프로토타입이기 쉽다. 오른쪽 아래는 비어 있다. LF 프로토타입으로는 구체적인 태스크를 수행할 수 없기 때문이다.

피그마 같은 도구로 만든 프로토타입이라면 플레이 링크를 준비하고 녹화 기능을 켜 둔다. 테스트 도중 첫 화면으로 돌아가야 할 때가 많으므로 진행자만 아는 숨겨진 홈버튼을 넣어 두는 것도 준비 사항이다.

### 참가자 모집과 진행

사용성 테스트에서 가장 중요한 요소는 프로토타입과 참가자이고, 참가자는 실제 사용자여야 한다. 다수를 모집할 때는 무작위로 늘리기보다 모집(Recruiting) 기준을 세워 선별(Screening)한다. 교재 표 3.5는 성별(남, 여)과 제품 사용 경험(전혀 없음, 경쟁사 제품 사용 경험, 동일 제품 사용 경험)으로 여섯 칸을 만들고 칸마다 3명씩 배정한 예다.

참가자 모집은 전문성을 요하지는 않지만 성가신 일이 되기 쉽다. 한 사람의 일정이 바뀌면 스케줄이 연쇄적으로 변하고, 애써 모집한 참가자가 나타나지 않기도 한다. 섭외할 때 예상 소요 시간, 테스트의 성격, 사례비를 미리 알린다.

| 비교 | 사전 조사 | 사후 조사 |
| --- | --- | --- |
| 시점 | 현장 도착 직후, 본 테스트 전 | 시스템을 써 본 뒤 |
| 목적 | 참가자 프로파일링 | 테스트 중 보인 행동에 대한 확인과 논의 |
| 형식 | 설문이 적합하다 | 인터뷰가 적합하다 |
| 주의 | 테스트에 영향을 주지 않아야 한다 | 참가자는 조작 행동을 잘 기억하지 못하므로 녹화 영상을 보여 주며 기억을 돕는다 |

사후 조사에서 녹화 영상을 보여 주는 것은 1주차 인터뷰에서 '기억력은 완벽하지 않다'는 유의점에 대해 사진이나 영상을 제공하라고 했던 것과 같은 처방이다.

**진행자의 태도.** 본 테스트 전에 파일럿 테스트를 한두 차례 해서 프로토타입, 태스크, 기록 시트, 카메라 앵글을 점검한다. 진행자는 참가자가 아니라 디자인 안을 평가한다는 점을 분명히 전한다. 디자인 시안을 변명하지 않는다. 고개를 젓거나 혀를 차는 부정적 반응은 금물이고, '잘했어요' 같은 긍정적 반응도 하지 않는다. 칭찬을 들으면 참가자는 진행자가 자신을 평가한다는 데 신경을 쓰기 때문이다. 가볍게 미소를 띠는 정도의 중립적이고 정중한 태도가 맞다.

**Think Aloud.** 참가자에게 생각을 소리 내어 말하게 하는 방법이다. 내면의 사고를 드러내 주지만 그만큼 인지적 부하가 생겨 태스크 수행에 부정적인 영향을 준다. 교재가 권하는 방법은 테스트를 두 명이 함께 하게 하는 것이다. 혼잣말은 부자연스럽지만 두 명이면 대화하듯 생각을 말하게 된다.

**기록 시트.** 녹화 영상을 다시 보며 정리하는 것은 시간이 많이 드는 비효율적인 방식이다. 기록 시트에 바로 적으면 이어지는 사후 인터뷰에서 '이렇게 조작하셨는데 어떤 의도였나요?' 같은 질문을 곧바로 할 수 있다. 양식이 잘 준비되어 있으면 체크만으로 기록할 수 있고, 기록 방식과 위치가 규격화되어 다른 사람이 봐도 이해하기 쉽다.

**데이터 분석.** 참가자가 다섯 명을 넘어가면 일정한 패턴이 나오고, 테스트를 멈추고 프로토타입을 고칠지 더 진행할지 판단이 선다. 얼굴 표정, 말, 행동 같은 질적 데이터는 연구자가 주관적으로 리포팅하고 적절히 가공해 그래프나 다이어그램으로 만든다. 성공 여부, 수행 시간 같은 양적 데이터는 평균과 표준편차, 빈도 분석, 교차 분석, 평균 비교로 통계 처리한다.

## 정리

5장 UI 디자인에서 기억할 것.

- UI는 물리적, 시각적, 청각적, 촉각적 요소의 통합이다. PUI는 전통적인 제품 디자인과, GUI는 정보 콘텐츠 디자인과 연결되고, 정보 구조와 워크플로는 심층에 있다
- 정전식은 전도체에 반응하고 멀티터치를 지원한다. 감압식은 누르는 힘에 반응해서 키오스크와 ATM에 쓰인다
- 몰입형 UI는 VR, AR, MR, XR, SR, BCI다. XR은 앞의 셋을 포괄하는 말이다
- 인터랙션 디자인의 원칙은 일관성, 피드백, 유연성, 사용자 제어다
- 개럿의 UX 요소 다섯 단계 중 UI 디자인의 범위는 구조, 프레임, 표면이다
- 어포던스는 깁슨이 소개하고 노먼이 대중화했다. 물리적, 지각적, 문화 관습적 어포던스로 나뉜다
- UX 라이팅의 나쁜 사례는 한 단어나 코드이고, 좋은 사례는 무엇을, 어떤 결과가, 어떻게, 얼마나를 문장으로 말한다

8장 사용성 테스트에서 기억할 것.

- 가장 연구가 오래된 분야이고 실험심리학의 영향을 받아 정량적이다. 프로젝트의 마지막 단계로 고정되지 않는다
- ISO의 사용성은 효과성, 효율성, 만족도다. 테스트는 평가보다 가볍고 실험보다 덜 엄밀하다
- 닐슨은 예산의 10%를 쓰라고 했고, 사용성에 가까운 항목일수록 개선 정도가 높았다. 좁고 명확한 문제에 효과적인 방법이다
- 합의된 방향은 전문가보다 사용자, 실험실보다 현장, 후기보다 초기부터 반복이다
- 참가자 다섯 명이면 사용성 문제의 80% 이상을 찾는다. 결론이 났으면 참가자를 늘리기보다 다음 프로토타입을 테스트한다
- 테스트 환경은 완벽할 필요가 없고 임장감을 주면 된다
- 휴리스틱 평가는 빠르고 해결책이 같이 나오지만 평가자가 실제 사용자가 아니다. 닐슨의 10가지 휴리스틱에는 오류 대책이 많고 와우포인트가 없다
- 설문 도구는 비교하기 쉽지만 점수의 이유를 알려 주지 않는다
- 진행의 원칙은 반복과 통합이다. 절차는 준비, 사용성 테스트, 분석이다
- 태스크는 상황을 먼저 주고 적당히 추상적으로, 정답이 드러나지 않게 쓴다
- 성공 여부는 효과성, 수행 시간은 효율성, 만족도는 만족도에 대응한다
- LF 프로토타입으로는 구체적인 태스크를 수행할 수 없다
- 진행자는 부정적 반응도 긍정적 반응도 하지 않는다. 평가 대상은 참가자가 아니라 디자인 안이다
