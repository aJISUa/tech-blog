ECC UX/UI 팀 8주차 스터디. 범위는 『실전 피그마』 PART 4 '피그마의 꽃, 오토 레이아웃 살펴보기'로 책의 104~145쪽이다. 11월 2일에 대면으로 모였고 7일까지가 8주차 기간이었다.

5주차에 PART 1~3에서 프레임, 도형, 정렬, 펜 도구를 익혔다. PART 1의 장점 표에서 '강력한 편의 기능'으로 소개되고, PART 3에서 프레임을 공부할 때 '오토 레이아웃과 컴포넌트는 모두 프레임 기반으로 동작한다'고 예고만 되었던 기능이 이번 주의 주제다. 다섯 장은 두 묶음으로 나뉜다.

| 장 | 제목 | 쪽 | 성격 |
| --- | --- | --- | --- |
| 1장 | 오토 레이아웃의 구성 요소 알아보기 | 106~118 | 이론과 실습. 패널 옵션을 하나씩 익힌다 |
| 2장 | 반응형 디자인을 위한 크기 조절 옵션 알아보기 | 119~124 | 이론과 실습. Hug, Fixed, Fill |
| 3장 | 버튼과 텍스트 필드 만들기 | 125~127 | 실습 |
| 4장 | 여러 가지 형태의 알림창 만들기 | 128~137 | 활용 예제 |
| 5장 | 프로필 카드 디자인하기 | 138~145 | 활용 예제 |

1~2장은 오토 레이아웃 패널의 옵션을 하나씩 익히는 단계이고, 3~5장은 그 옵션을 조합해 버튼, 알림창, 프로필 카드를 만드는 단계다. 뒤로 갈수록 오토 레이아웃을 중첩해서 쓴다. 실습은 이번에도 Figma 파일의 'PART 4' 페이지에 섹션 01~05로 책 수치대로 만들었고, 이 글의 캡처는 모두 그 파일에서 결과물만 내보낸 것이다. 글꼴은 5주차와 같은 이유로 한글은 Noto Sans KR, 영문·숫자는 Inter로 대신했다.

## 1장. 오토 레이아웃의 구성 요소 알아보기

교재는 오토 레이아웃을 이렇게 소개한다.

> 피그마의 오토 레이아웃은 매우 강력한 기능으로, 반응성과 유연성이 뛰어난 동적 레이아웃을 만들 수 있다.

오토 레이아웃은 기본으로 프레임에 속성이 포함되어 있고, 프레임 내부 구성 요소들의 배열 방향, 간격, 패딩, 정렬 같은 옵션을 설정한다. 하는 일은 두 방향이다.

| 방향 | 내용 |
| --- | --- |
| 콘텐츠 → 프레임 | 내부 콘텐츠의 크기에 따라 프레임 크기가 자동으로 조절된다 |
| 프레임 → 콘텐츠 | 반대로 프레임 크기에 따라 콘텐츠의 크기가 자동으로 조정된다 |

그래서 디자인 내용이 수정될 때 각 요소의 크기나 위치를 직접 편집할 필요가 없고, 디자인 프로세스를 크게 단축할 수 있다.

### 생성과 방향

오토 레이아웃을 만드는 방법은 세 가지다.

| # | 방법 |
| --- | --- |
| 1 | 오브젝트를 선택한 상태에서 `Shift+A` |
| 2 | 프레임을 선택한 상태에서 Auto layout 패널의 '+' 아이콘 |
| 3 | 프레임이나 오브젝트를 선택한 상태에서 오른쪽 클릭 → Add auto layout |

'+'를 누르기 전에는 Auto layout 패널이 비어 있고, 누르면 방향 아이콘과 간격 8, 패딩 8이 기본값으로 나타난다.

| 단계 | 할 일 | 수치·결과 |
| --- | --- | --- |
| 01 | `R`로 사각형 | 80×40, FFEC40 |
| 02 | `Shift+A` → 사각형이 새 프레임으로 감싸지고 Auto layout 패널이 활성화된다. 구분을 위해 프레임에 Fill | 7636FF, Hug×Hug |
| 03 | 노란 사각형을 `Ctrl+D` 두 번 | 보라색 컨테이너가 함께 늘어난다 |
| 04 | 새 사각형을 컨테이너 안으로 드래그해 추가, 기존 오브젝트를 밖으로 빼기도 한다 | FF5B5B |
| 05 | 오브젝트를 선택하고 방향키 | 배열 순서가 바뀐다 |

02단계 옆 TIP이 오토 레이아웃의 전제를 하나 알려 준다. 오토 레이아웃은 오직 프레임에서만 설정할 수 있다. 그룹으로 묶인 오브젝트나 단일 오브젝트에 오토 레이아웃을 걸면 최상위 요소가 자동으로 프레임으로 바뀐다.

프레임 안 오브젝트가 나열되는 방향은 Auto layout 패널의 세 아이콘으로 바꾼다.

| 아이콘 | 결과 |
| --- | --- |
| Vertical layout(↓) | 내부 오브젝트가 수직(세로 방향)으로 배열된다 |
| Horizontal layout(→) | 수평(가로 방향)으로 배열된다 |
| Wrap(↩) | 상위 컨테이너 크기가 줄어들 때 내부 오브젝트가 자동으로 줄바꿈된다 |

![Vertical, Horizontal, Wrap]({{ '/assets/images/club-ecc-ux-ui/figma-p4-direction.png' | relative_url }})

교재 그림과 같은 간격 24, 패딩 40으로 만든 결과다. 왼쪽부터 Vertical, Horizontal, Wrap이다. Wrap은 Horizontal과 같은 가로 배열인데 프레임 너비를 300으로 줄이자 세 번째 오브젝트가 다음 줄로 내려갔다. 교재 TIP대로 Wrap은 수평 방향(가로)에만 적용된다.

### 간격과 패딩

간격은 오브젝트 사이의 거리이고, 패딩은 오브젝트와 프레임 사이의 크기다.

| 항목 | 내용 |
| --- | --- |
| 간격 | 하나의 프레임 내부에 있는 모든 오브젝트는 같은 간격을 가진다. 오브젝트별로 간격을 다르게 하려면 오토 레이아웃을 중첩해야 한다 |
| 음수 간격 | '−'를 넣어 음수로도 설정할 수 있다 |
| Wrap일 때 | 가로 간격과 세로 간격을 각각 따로 설정한다 |
| 패딩 | Horizontal padding과 Vertical padding을 바꾼다. 'Individual padding' 아이콘을 누르면 상하좌우 4방향을 각각 다르게, `Ctrl`을 누르고 패딩을 클릭하면 4방향을 한 번에 설정한다 |

간격 규칙의 첫 줄이 이번 PART 전체를 관통한다. 한 프레임 안의 간격은 하나뿐이라서, 제목과 내용 사이는 8, 텍스트 묶음과 버튼 묶음 사이는 24처럼 간격을 다르게 주려면 프레임을 나누어 겹쳐 넣을 수밖에 없다. 4~5장의 알림창과 프로필 카드가 모두 이 방식으로 만들어진다.

Auto layout 패널을 쓰지 않고 캔버스에서 바로 고칠 수도 있다. 오브젝트 사이에 커서를 가져가면 분홍색 빗금 영역이 나타나고, 이 영역을 드래그하거나 클릭해 간격과 패딩을 수정한다.

| 조작 | 동작 |
| --- | --- |
| 빗금 영역 드래그 / 클릭 | 간격·패딩 변경 / 직접 수치 입력 |
| `Alt`+드래그, `Alt`+클릭 | 반대 방향의 패딩을 동시에 변경 |
| `Shift`+드래그 | Big nudge에 설정된 값만큼 변경 |
| `Alt+Shift`+드래그, `Alt+Shift`+클릭 | 모든 방향을 동시에 변경 |
| 입력창이 열린 상태에서 `Tab` | 위쪽 → 오른쪽 → 아래쪽 → 왼쪽 순서로 입력창 이동 |

`Shift`+드래그의 Big nudge는 5주차 PART 2에서 8로 바꿔 둔 그 값이다.

### 정렬과 분배

정렬은 Auto layout 패널의 정렬 상자에서 9가지 방향 중 하나를 고른다. 정렬 상자를 선택한 상태에서 방향키나 `W` `A` `S` `D` `H` `V`로도 바꾼다. PART 3에서 외운 정렬 단축키가 여기서도 쓰인다. 단, 교재의 Why?가 짚듯 프레임이 'Hug×Hug'인 상태에서는 오브젝트와 프레임 사이에 여유 공간이 없어서 정렬 방향이 바뀌지 않는다.

분배는 'Advanced auto layout settings' 아이콘(…)의 Spacing mode에서 바꾼다.

| Spacing mode | 동작 |
| --- | --- |
| Packed | 오브젝트들이 지정된 간격만큼 배열된다 |
| Space between | 오브젝트들이 프레임 전체에 걸쳐 같은 간격으로 배열된다 |

| 단계 | 할 일 | 수치·결과 |
| --- | --- | --- |
| 01 | `O`로 원 3개 → 색 → Stroke | 80×80, FF4040·FFBF1A·3E74FF, 두께 4 |
| 02 | 원 모두 선택 → `Shift+A` → 간격·패딩 → 프레임에도 Fill과 Stroke | 32 / 24, FFFFFF / 000000 두께 4 |
| 03 | 간격의 확장 아이콘 → 'Auto' | 정렬 상자 아이콘이 바뀌고 Spacing mode가 Space between이 된다 |
| 04 | 프레임 오른쪽 끝을 드래그 | 오브젝트들이 동일한 간격을 유지하며 따라 움직인다 |

정렬 상자를 클릭한 상태에서 `X`를 누르면 Spacing mode가 전환된다.

![Packed(간격 32)와 Space between(간격 Auto)]({{ '/assets/images/club-ecc-ux-ui/figma-p4-spacing-mode.png' | relative_url }})

위가 Packed, 아래가 같은 원 세 개를 Space between으로 바꾸고 프레임을 560으로 늘린 결과다. Packed는 간격 32가 고정이라 프레임이 원 세 개와 패딩만큼만 차지한다. Space between은 간격 칸에 숫자 대신 'Auto'가 들어가고, 프레임 너비에서 패딩과 원을 뺀 나머지를 원 사이에 똑같이 나눠 준다.

### Advanced auto layout settings

같은 '…' 아이콘 안에 옵션이 세 개 더 있다.

| 옵션 | 값 | 내용 |
| --- | --- | --- |
| Strokes | Excluded from layout / Included in layout | 오브젝트 외곽선 크기가 오토 레이아웃 프레임에서 공간을 차지할지 고른다 |
| Canvas stacking | Last on top / First on top | 오브젝트가 겹칠 때 맨 위에 표시되는 순서를 고른다 |
| Align text baseline | – / ✓ | 텍스트를 폰트의 기준선에 맞춰 정렬한다 |

Strokes 옵션이 필요한 이유를 교재는 이렇게 설명한다. 피그마는 기본으로 오토 레이아웃의 프레임 크기를 계산할 때 오브젝트의 선 두께를 고려하지 않는다. 이 때문에 개발자와의 커뮤니케이션에서 일부 간극이 생길 수 있다. 실습은 앞의 원 세 개를 그대로 쓴다. 원의 Stroke 위치를 Outside로 바꾼 다음 Strokes를 Included로 바꾸면, 간격과 패딩이 원의 선 두께에 영향을 받아 프레임 크기가 바뀐다.

Canvas stacking은 오브젝트가 겹칠 때 의미가 있다. 원 세 개를 Space between으로 둔 채 프레임 크기를 줄여 겹치게 만들면, 기본값인 Last on top에서는 레이어의 마지막 오브젝트(파란 원)가 맨 위에 온다. First on top으로 바꾸면 첫 오브젝트(빨간 원)가 맨 위로 온다.

![Strokes Excluded·Included와 Canvas stacking Last on top·First on top]({{ '/assets/images/club-ecc-ux-ui/figma-p4-strokes-stacking.png' | relative_url }})

왼쪽 위가 Strokes Excluded, 왼쪽 아래가 Included다. 같은 원 세 개인데 아래쪽 프레임이 가로·세로로 조금씩 더 크다. 바깥쪽으로 4px씩 나간 원의 테두리가 간격과 패딩 계산에 들어갔기 때문이다. 오른쪽은 너비 240으로 줄여 겹친 원이고, 위가 Last on top, 아래가 First on top이다. 레이어 순서는 그대로인데 화면에서 맨 위에 보이는 원만 파랑에서 빨강으로 바뀌었다.

Align text baseline은 크기가 다른 텍스트에 쓴다. '50,000'(18)과 '원'(14)을 간격 2로 묶으면 기본 정렬로는 두 글자의 아래선이 맞지 않는다. Align text baseline을 체크하거나 정렬 상자를 클릭한 상태에서 `B`를 누르면 폰트의 기준선에 맞춰 정렬된다. 교재 TIP은 서로 다른 종류의 폰트를 쓰는 경우에도 이 옵션으로 정렬을 깔끔하게 만들 수 있다고 한다.

### Absolute position과 해제

Absolute position(절대 위치)을 쓰면 오토 레이아웃이 걸린 프레임 안에 오토 레이아웃 옵션의 영향을 받지 않는 오브젝트를 추가할 수 있다. 내부 오브젝트를 강조하거나, 오토 레이아웃을 해제하지 않고 다른 디자인 요소를 넣고 싶을 때 쓴다.

| 단계 | 할 일 | 수치·결과 |
| --- | --- | --- |
| 01 | Space between으로 둔 원 세 개 옆에 원을 하나 더 그린다 | 40×40, 3AFF95 |
| 02 | 새 원을 프레임 오른쪽에 넣고 Transform 패널 오른쪽 위의 'Absolute position' 아이콘 | X 176, Y 24 |
| 03 | Constraints 지정 → 초록 원을 프레임 오른쪽 상단으로 | Right, Top |
| 04 | 프레임 조절점을 오른쪽으로 드래그해 늘린다 | 초록 원이 따라간다 |

![Absolute position: Constraints Right·Top과 프레임을 늘린 상태]({{ '/assets/images/club-ecc-ux-ui/figma-p4-absolute.png' | relative_url }})

왼쪽이 03단계, 오른쪽이 프레임을 늘린 04단계다. 초록 원은 오토 레이아웃의 흐름에서 빠져 있어서 원 세 개의 간격 계산에 들어가지 않고, 프레임 모서리에 걸쳐 있어도 다른 원을 밀어내지 않는다. 오브젝트를 절대 위치로 지정하면 (Design) 탭에 Constraints 패널이 다시 나타나는데, Right·Top으로 정해 두었기 때문에 프레임이 늘어나도 오른쪽 위 모서리를 따라간다. 5주차 PART 3에서 프레임의 Constraints를 배운 것이 이 자리에서 다시 쓰인다. 교재는 이 기능이 아이콘의 알림 표시 같은 것을 만들 때 쓰인다고 한다.

프레임 안의 오브젝트를 옮길 때 `Spacebar`를 누른 채 드래그하면 오브젝트가 프레임 바깥으로 빠져나가지 않는다. 오토 레이아웃을 해제할 때는 Auto layout 패널의 '−' 아이콘을 누르거나 `Shift+Alt+A`를 누른다.

## 2장. 반응형 디자인을 위한 크기 조절 옵션 알아보기

크기 조절 옵션은 오토 레이아웃 프레임과 그 하위 오브젝트 사이의 상관관계를 설정해 크기 조정이 유기적으로 이루어지게 하는 옵션이다. 교재가 예로 드는 것은 텍스트 길이에 따라 자동으로 늘어나는 입력창, 전체 프레임 너비에 맞춰 자동으로 조정되는 상품 카드다.

### Hug, Fixed, Fill

| 비교 | Hug contents | Fixed size | Fill container |
| --- | --- | --- | --- |
| 설정하는 곳 | 오브젝트를 감싸는 상위 프레임 | 프레임과 내부 오브젝트 모두 | 프레임 내부 오브젝트 |
| 크기를 정하는 것 | 하위 오브젝트 크기 + 패딩 | 임의의 고정값 | 상위 프레임 크기 − 패딩 |
| 교재 계산 | 100 + 20×2 = 140 | W 300 | 400 − 20×2 = 360 |
| Transform에서 직접 수정 | 안 된다 | 드래그·입력으로 된다 | 안 된다 |
| 교재의 비유 | 고무줄처럼 탄력적으로 감싼다 | | 컵에 물을 채우듯 패딩을 뺀 영역을 가득 채운다 |

실습은 하나의 프레임으로 이어진다.

| 옵션 | 단계 | 결과 |
| --- | --- | --- |
| Hug | 100×100 노란 사각형(FFEC40)에 `Shift+A`, 파란 프레임, 패딩 20 | 프레임 140×140, Hug×Hug |
| | 안쪽 사각형 W를 200으로 | 프레임도 240으로 따라 커진다 |
| Fixed | 프레임 오른쪽 조절점을 드래그해 W 300 | Horizontal resizing이 Hug에서 Fixed로 바뀐다 |
| | 안쪽 사각형을 드래그해 늘린다 | 프레임은 300 그대로, 사각형(382)만 밖으로 넘친다 |
| Fill | 노란 사각형의 Horizontal resizing을 Fill container로, 프레임을 400으로 | 사각형이 360이 된다 |
| | Fill 사각형을 `Ctrl+D` 두 번 | 세 개가 균일한 비율로 나뉜다(114.67) |

![Hug contents, Fixed size, Fill container]({{ '/assets/images/club-ecc-ux-ui/figma-p4-resizing.png' | relative_url }})

맨 윗줄이 Hug, 가운데 줄이 Fixed, 아랫줄이 Fill이다. 윗줄은 사각형이 100에서 200으로 커지자 파란 프레임이 패딩 20을 유지한 채 따라 커졌다. 가운데 줄 오른쪽에서는 프레임이 300으로 고정되어 있어서 사각형만 프레임 밖으로 튀어나왔다. 교재 Why?의 설명대로 Horizontal resizing이 Fixed로 바뀌는 순간 Hug contents의 속성을 잃기 때문이다. 아랫줄은 반대 방향이다. 사각형이 아니라 프레임 크기를 정했고, 사각형 세 개는 남은 공간을 나눠 가졌다. 크기가 백분율로 조정되기 때문에 114.67처럼 소수점이 생길 수 있다.

Hug와 Fill이 Transform 패널에서 크기를 직접 고칠 수 없는 이유는 같다. 둘 다 크기가 다른 요소로부터 계산되기 때문이다. Hug는 안에서 밖으로, Fill은 밖에서 안으로 계산된다. 교재도 Fill container를 Hug contents와 반대 성격을 가지는 옵션이라고 정리한다.

### 중첩된 오토 레이아웃 리사이징

오토 레이아웃을 단일로 쓰면 크기 조절 옵션은 두 가지만 표시된다. 중첩하면 위치에 따라 보이는 옵션이 달라진다.

| 위치 | 표시되는 옵션 |
| --- | --- |
| 최하위 오브젝트 | Fixed width, Fill container |
| 중첩된(중간) 프레임 | Fixed width, Hug contents, Fill container |
| 최상위 프레임 | Fixed width, Hug contents |

중간 프레임만 세 가지가 다 나오는 이유는 하위 오브젝트와 상위 프레임의 역할을 동시에 하기 때문이다. 최하위에는 감쌀 것이 없어서 Hug가 없고, 최상위에는 채울 상위 프레임이 없어서 Fill이 없다.

> 중첩된 오토 레이아웃에서 최하위 요소를 반응형으로 만들려면 중간 프레임과 최하위 오브젝트 모두 크기 조절 옵션을 'Fill container'로 지정해야 한다.

![중첩 리사이징: 모두 Fill / 최하위 Fixed / 중간 Hug]({{ '/assets/images/club-ecc-ux-ui/figma-p4-nested.png' | relative_url }})

세 개 모두 최상위 프레임을 같은 너비(360)로 둔 결과다. 왼쪽은 중간 프레임과 최하위 빨간 사각형이 모두 Fill이라서 빨간 사각형이 끝까지 늘어났다. 가운데는 중간 프레임은 Fill이지만 최하위가 Fixed width라서 중간 프레임만 늘어나고 빨간 사각형은 그대로다. 오른쪽은 최하위가 Fill이어도 중간 프레임이 Hug라서 중간 프레임부터 늘어나지 않았다. 둘 중 하나라도 Fill container가 아니면 최하위 오브젝트는 자동으로 늘어나지 않는다.

## 3장. 버튼과 텍스트 필드 만들기

오토 레이아웃을 쓰는 가장 기본 형태의 디자인 요소로 기본 사용법을 익힌다.

| 단계 | 버튼 | 텍스트 필드 |
| --- | --- | --- |
| 01 | `T`로 '버튼' (Pretendard Bold 14) | `T`로 '텍스트 필드' (Pretendard Regular 14) |
| 02 | `Shift+A` → 프레임 Fill 2269F3, 텍스트 FFFFFF | `Shift+A` → Fill FFFFFF, Stroke DEDEDE |
| 03 | 패딩 H 24 / V 12, 정렬 가운데, Corner radius 8 | 패딩 H 16 / V 12, 정렬 왼쪽-가운데, 오른쪽 조절점 드래그로 Hug → Fixed 240, Corner radius 8, 이름 'Text field' |
| 04 | 이름 'Button', 텍스트를 바꾸면 프레임 길이도 함께 바뀐다 | 안쪽 텍스트의 Horizontal resizing을 Fill container로 |
| 05 | | 텍스트를 길게 입력하면 너비를 벗어나지 않고 아래로 늘어난다 |

![버튼과 텍스트 필드]({{ '/assets/images/club-ecc-ux-ui/figma-p4-button-textfield.png' | relative_url }})

윗줄은 같은 버튼에 '버튼'과 '텍스트를 변경해 보세요'를 넣은 결과다. 프레임이 Hug라서 글자가 길어진 만큼 버튼이 가로로 늘어났고, 패딩 24/12는 그대로다. 아랫줄은 텍스트 필드에 짧은 글과 긴 글을 넣은 결과다. 프레임 가로를 240으로 고정하고 안쪽 텍스트를 Fill container로 두었기 때문에, 긴 글은 옆으로 넘치지 않고 줄바꿈되며 아래로 늘어났다.

두 요소의 설정을 나란히 놓으면 차이가 크기 조절 옵션에 있다.

| 비교 | Button | Text field |
| --- | --- | --- |
| 프레임 가로 | Hug (텍스트 길이 따라 늘어남) | Fixed 240 |
| 프레임 세로 | Hug | Hug (텍스트가 아래로 늘어남) |
| 텍스트 가로 | Hug | Fill container |
| 패딩 H / V | 24 / 12 | 16 / 12 |
| 정렬 | 가운데 | 왼쪽-가운데 |

텍스트 필드에는 Why?가 하나 붙어 있다. 03단계에서 실수로 대각선 조절점을 드래그해 프레임의 Vertical resizing까지 Fixed로 바뀌면, 텍스트가 길어져도 프레임이 상하로 늘어나지 않는다. 텍스트 길이에 따라 프레임이 아래로 늘어나지 않으면 Vertical resizing이 Hug로 되어 있는지 확인한다.

## 4장. 여러 가지 형태의 알림창 만들기

알림창은 사용자가 파괴적인 행동을 할 때 경고를 주거나 사용자의 행동을 확인하는 역할을 한다. 기본형을 만든 다음 오토 레이아웃 옵션만 바꿔서 세 가지 변형을 만든다.

### 기본형 알림창

17단계로 길지만 순서는 안쪽에서 바깥쪽이다.

| 단계 | 할 일 | 수치·설정 |
| --- | --- | --- |
| 01~02 | 3장의 버튼을 `Alt`+드래그로 복제 → 복제본을 외곽선형으로 | Fill FFFFFF, 외곽선·텍스트 2269F3 |
| 03~06 | 두 버튼 `Shift+A` → 'Actions'(간격 8) → Hug에서 Fixed 200 → `Enter`로 버튼 모두 선택 → Fill container → `\`로 다시 Actions → 너비 변경 | 버튼이 1:1을 유지하며 함께 늘어난다 |
| 07~08 | '제목'과 '내용' 입력 → `Shift+A` → 'Contents' | 제목 Bold 16 / 내용 Medium 14, 간격 8, 정렬 가운데 상단 |
| 09~11 | Contents와 Actions `Shift+A` → 'Alert' | 간격 24, 패딩 24, Fill FFFFFF, Corner radius 12 |
| 12 | 오른쪽 가운데 조절점 드래그 → Fixed | W 320 |
| 13~15 | `Enter`로 Contents·Actions 선택 → Fill container → Contents 안 텍스트도 Fill container → Text align center | |
| 16~17 | 반응형 기본형 완성 → 텍스트 변경 | 320×Hug |

`Enter`는 레이어의 하위 요소를 한 번에 모두 선택하고, `Shift+Enter`나 `\`는 상위 요소로 돌아간다. 패딩이나 크기 조절 옵션을 바꿀 때 자주 쓰는 단축키라고 교재 TIP이 알려 준다.

레이어 구조로 정리하면 이렇다.

| 레이어 | 방향 | 간격 | 패딩 | 크기 조절 |
| --- | --- | --- | --- | --- |
| Alert | Vertical | 24 | 24 / 24 | Fixed 320 × Hug |
| └ Contents | Vertical | 8 | 0 | Fill × Hug |
| 　└ 제목 / 내용 | | | | Fill × Hug, Text align center |
| └ Actions | Horizontal | 8 | 0 | Fill × Hug |
| 　└ Button ×2 | Horizontal | | 24 / 12 | Fill × Hug |

1장에서 본 간격 규칙이 이 표에 그대로 보인다. 제목과 내용 사이는 8, 텍스트 묶음과 버튼 묶음 사이는 24로 간격이 다르기 때문에 Contents와 Actions를 따로 만든 다음 Alert로 한 번 더 감쌌다. 13단계에서 너비를 바꿨을 때 버튼이 함께 늘어나는 것은 06단계에서 버튼을 미리 Fill container로 지정해 두었기 때문이고, 17단계에서 문구를 바꿔도 가운데 정렬이 유지되는 것은 Contents와 그 안의 텍스트를 모두 Fill container로 두었기 때문이다. 2장의 중첩 리사이징 조건이 그대로 적용된 것이다.

### 단일 버튼, 수직형 버튼, 시스템형

기본형에서 바꾸는 옵션은 몇 개뿐이다.

| 유형 | 바꾸는 곳 | 바꾸는 옵션 | 쓰임 |
| --- | --- | --- | --- |
| 단일 버튼 | 왼쪽 Button | Layer 패널의 '눈' 아이콘으로 숨기기(`Ctrl+Shift+H`) | 구매 완료 같은 안내 |
| 수직형 버튼 | Actions | Vertical layout, 파란 버튼을 `↑`로 위로 | 버튼에 쓰는 텍스트가 길 때 |
| 시스템형 | 제목·내용 / Button / Actions | Text align left / Hug / 정렬 오른쪽 중앙 | 웹 브라우저에서 기본으로 쓰는 형태 |

![알림창 네 가지: 기본형, 단일 버튼, 수직형 버튼, 시스템형]({{ '/assets/images/club-ecc-ux-ui/figma-p4-alerts.png' | relative_url }})

왼쪽 위부터 기본형, 단일 버튼, 수직형 버튼, 시스템형이다. 단일 버튼은 왼쪽 버튼을 지운 것이 아니라 숨긴 것이고, 남은 버튼이 Fill container라서 Actions 전체 너비를 혼자 채웠다. 수직형은 Actions의 방향만 세로로 바꿨는데 두 버튼이 모두 Fill이라 같은 너비로 쌓였다. 시스템형은 버튼을 Hug로 줄이고 Actions의 정렬을 오른쪽 중앙으로 옮겨서, 텍스트는 왼쪽, 버튼은 오른쪽에 놓였다. 교재 TIP은 시스템형에서도 필요 없는 버튼을 숨겨 단일 버튼으로 쓸 수 있다고 한다.

수직형 알림창의 제목은 교재 128쪽 완성 예시에는 '작성중인 글이 있어요.'로, 136쪽 실습 그림에는 '작성중인 글이 있습니다'로 나온다. 캡처는 실습 그림을 따랐다. 그리고 130쪽 05단계 본문은 버튼의 'Horizontal padding'을 Fill container로 바꾸라고 적었는데, 같은 쪽 그림의 패널은 Horizontal resizing이다. 패딩에는 Fill container라는 값이 없으므로 resizing이 맞다.

## 5장. 프로필 카드 디자인하기

> 오토 레이아웃을 서로 다른 방향으로 중첩해서 사용하면 다양한 형태의 반응형 레이아웃을 디자인할 수 있다.

교재는 이것으로 이미지, 텍스트, 버튼, 아이콘으로 구성된 프로필 영역이나 채팅 목록 같은 요소를 만든다고 소개한다.

### 디자인 요소 만들기

| 단계 | 할 일 | 수치·설정 |
| --- | --- | --- |
| 01 | `F`로 프레임 → Corner radius → 이름 | 48×48, 24, 'Img-wrap' |
| 02 | `R`로 사각형 → 이름 | 48×48, 'Img' |
| 03~04 | '닉네임', '자기소개' | Pretendard Semibold 16 / Regular 14 |
| 05 | '팔로우' 텍스트(FFFFFF) → `Shift+A` → 패딩·정렬·Corner radius → Fill → 이름 | 16 / 8, 가운데, 8, 0048FF, 'Button' |
| 06~07 | 리소스 도구(`Shift+I`) → (Plugins) → 'unsplash' → 도형 선택 후 Insert Random | 도형에 이미지 삽입 |
| 08 | 이미지 도형을 Img-wrap 안으로 → `Alt+H`/`Alt+V` → Img의 Constraints | Scale – Scale |

Unsplash는 상업 용도로 이용할 수 있는 무료 이미지를 제공하는 웹 사이트이고, 그 플러그인으로 도형에 이미지를 넣는다. 08단계의 Why?가 이미지를 프레임 안에 넣는 이유를 설명한다. 이미지를 사각형이나 원에 직접 넣으면 그 형태로만 내보낼 수 있다. 프레임에 넣으면 안쪽 'Img'를 선택해 사각형으로, 바깥 'Img-wrap'을 선택해 원형으로 추출할 수 있어서 원본 소스를 유지하고 활용도를 높인다. Figma 파일에서는 Unsplash 이미지 대신 도형으로 그린 캐릭터 일러스트를 Img에 넣었다.

### 오토 레이아웃과 크기 조절

| 단계 | 대상 | 설정 |
| --- | --- | --- |
| 1 | 닉네임 + 자기소개 → 'Text' | 세로, 간격 0 |
| 2 | Img-wrap + Text → 'Profile-info' | 가로, 간격 12 |
| 3 | Profile-info + Button → 'Profile-card' | 가로, 간격 16, `Ctrl`+패딩 클릭으로 모든 패딩 24, Corner radius 12, Fill FFFFFF |
| 4 | Profile-card를 오른쪽으로 늘린다 | 400×Hug |
| 5 | Profile-info → Text → Text 안 텍스트 | 모두 Horizontal resizing Fill container |
| 6 | Profile-card 너비를 줄였다 늘렸다 | 텍스트가 줄바꿈되면 완성 |

레이어 이름은 자기만의 규칙이나 팀 룰에 맞춰 자유롭게 정해도 된다고 교재가 덧붙인다. 높이가 텍스트 길이를 따라가게 하려면 Vertical resizing은 Hug로 남겨 둔다.

### 말줄임표 처리

자기소개 텍스트를 선택하고 Text 패널의 'Type settings' 아이콘(…)에서 'Truncate text'를 켜면, 지정된 줄 수를 넘는 텍스트가 말줄임표(...)로 표시된다. Max lines의 숫자로 최대 줄 수를 정하는데 예제는 기본값 1을 썼다.

![프로필 카드: 400×Hug, 266×Hug 줄바꿈, Truncate text]({{ '/assets/images/club-ecc-ux-ui/figma-p4-profile-card.png' | relative_url }})

왼쪽 위가 Profile-card를 400으로 늘린 결과, 오른쪽이 266으로 줄인 결과, 왼쪽 아래가 자기소개를 길게 쓰고 Truncate text를 켠 결과다. 400일 때는 Profile-info가 남은 공간을 채워서 버튼이 카드 오른쪽 끝에 붙었다. 266으로 줄이면 Text가 좁아지면서 자기소개가 두 줄로 줄바꿈되고, 세로가 Hug라서 카드 높이도 따라 커졌다. 왼쪽 아래는 같은 400 카드인데 자기소개가 한 줄을 넘는 부분이 '…'로 잘려서 카드 높이가 그대로다. 같은 카드가 너비에 따라 줄바꿈과 말줄임 두 가지로 반응하는데, 줄바꿈은 2장의 Fill container가, 높이 고정은 Max lines가 정한다.

교재는 마지막에 Img-wrap에 이미지를 강조하는 링이나 접속중 표시를 더하고 버튼 내용을 바꾸거나 아이콘을 추가하면, 같은 레이아웃으로 프로필 카드뿐 아니라 다양한 목적의 디자인 컴포넌트를 만들 수 있다고 정리한다. 138쪽의 완성 예시가 그것이다. 팔로잉 버튼이 달린 Producer, 버튼이 없는 Engineer, 배지(82)가 달린 Chat-room이 모두 같은 구조에서 나왔다.

## 정리

1장 오토 레이아웃의 구성 요소에서 기억할 것.

- 만드는 법은 `Shift+A`, Auto layout 패널의 '+', 오른쪽 클릭 Add auto layout 세 가지다. 오토 레이아웃은 프레임에서만 설정되고, 그룹이나 단일 오브젝트에 걸면 최상위가 프레임으로 바뀐다
- 방향은 Vertical, Horizontal, Wrap이고 Wrap은 가로에만 적용된다
- 한 프레임 안의 간격은 하나뿐이다. 간격을 다르게 주려면 오토 레이아웃을 중첩한다
- 프레임이 Hug×Hug면 여유 공간이 없어서 정렬이 바뀌지 않는다
- Spacing mode는 Packed(지정 간격)와 Space between(전체에 같은 간격)이다
- 피그마는 기본으로 선 두께를 프레임 크기 계산에서 뺀다. Strokes를 Included로 바꾸면 포함된다
- Absolute position은 오토 레이아웃을 해제하지 않고 흐름에서 빠진 오브젝트를 넣는다. 아이콘의 알림 표시에 쓴다

2장 크기 조절 옵션에서 기억할 것.

- Hug는 하위 + 패딩, Fixed는 고정값, Fill은 상위 − 패딩이다. Hug는 안에서 밖으로, Fill은 밖에서 안으로 계산된다
- 프레임을 드래그해 크기를 바꾸면 Fixed가 되고 Hug의 속성을 잃는다
- 중간 프레임에만 세 가지 옵션이 다 나온다. 최하위를 반응형으로 만들려면 중간 프레임과 최하위를 모두 Fill container로 둔다

3~5장 실습에서 기억할 것.

- 버튼은 가로 Hug라서 글자를 따라 늘어나고, 텍스트 필드는 가로 Fixed와 텍스트 Fill이라서 아래로 늘어난다. 아래로 안 늘어나면 Vertical resizing이 Hug인지 확인한다
- 알림창은 Contents와 Actions를 나눠 만든 뒤 Alert로 감싼다. 변형 세 가지는 버튼 숨기기, Actions 세로 배열, 텍스트 왼쪽 정렬과 버튼 Hug·오른쪽 정렬로 만든다
- 이미지는 Img-wrap 프레임 안에 넣어 사각형과 원형으로 모두 내보낼 수 있게 한다
- 프로필 카드는 Profile-info, Text, 텍스트를 모두 Fill로 두고 세로는 Hug로 남긴다. 줄 수를 제한하려면 Truncate text와 Max lines를 쓴다
