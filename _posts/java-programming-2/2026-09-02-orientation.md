## 수영 그림으로 시작한 OT

OT 첫 슬라이드가 수영하는 그림이었다. 교수님께서 1학년 때부터 프로그래밍 수업에서 물장구라도 제대로 쳐봤는지, 책이랑 영상만 본 건 아닌지 생각해보라고 하셨다. 팔다리를 다 휘저어 보고, 숨 쉬면서 왔다 갔다 할 수 있어야 수영을 한다고 말할 수 있다고.

상속, 다형성, 캡슐화도 말로만 들어서는 모르고 직접 해봐야 알게 되는 거라 실습을 많이 해야 한다고 하셨다. "레시피 100개 외워도 라면 하나 못 끓이면 소용없다"는 말이 기억에 남는다.

> GPT가 있어도, 제미나이가 있어도 결국 중요한 건 스스로 해보는 것. 코딩 근육을 키우자.

## 자프실1이랑 뭐가 다른가

자프실1에서는 기본 문법이랑 OOP 개념(상속, 다형성, 캡슐화, 예외처리, 제네릭/컬렉션)을 배우고 Hunter & Animal, Battle 같은 미니 프로젝트를 했다.

자프실2는 그걸 바탕으로 한 단계 더 나간다.

- 고급 문법: 여러 컬렉션, GUI, 멀티스레드, 네트워크, JDBC
- OOP 응용: SOLID, 디자인 패턴 기초, 리팩토링
- SW 개발 과정 실습: Spring Boot(REST API, Spring Data JPA), 백엔드 기초
- 미니 프로젝트: 앱 채팅, 웹 채팅 같은 것

한 줄로 줄이면 "자바 백엔드에서 실무에 필요한 영역을 한 번씩 훑어보자"는 수업이다. 설계 원칙, 리팩토링, 클린 코드 쪽은 현업 5년 차, 10년 차 개발자도 다시 공부하는 분야라고 하셨다.

### 왜 이런 걸 배우는지

GUI(Swing)는 요즘 실무에서 거의 안 쓰는데도 다루는 이유가 GUI의 기본 구조를 한 번 경험해보기 위해서라고 한다. 코드를 외울 필요는 없고 WindowBuilder로 끌어다 쓰면 된다.

멀티스레드는 요즘 웹 프레임워크 안에 다 들어 있지만, 운영체제 수업에서 배울 개념을 미리 써보는 의미가 있다. 네트워크랑 JDBC도 컴퓨터네트워크, 데이터베이스 수업이랑 이어진다.

리팩토링이랑 클린 코드는 협업 때문이다. 코드는 내가 한 번 짜지만 다른 사람은 여러 번 읽는다. 그래서 누가 봐도 읽기 쉽고 고치기 쉬운 코드가 필요하다.

기술 면접 얘기도 해주셨는데, 코딩테스트는 몇 달 빡세게 준비하면 늘지만 기술 면접은 내가 해본 경험을 바탕으로 말하는 거라 하루아침에 안 된다고 하셨다. 그래서 수업 안에서 프로젝트 경험을 쌓아두라고.

## 이번 학기에 쓰는 도구

- Amateras: 처음 설계할 때. 드래그 앤 드롭 방식
- PlantUML: 이미 있는 코드 구조를 파악할 때. 스크립트 방식
- WindowBuilder: GUI 화면 만들 때
- JDBC, STS4: DB 연동, Spring Boot
- Lombok 같은 외부 라이브러리

## 이번 학기에 만들어볼 것들

- 알낳기: 닭이 이동하다가 스페이스를 누르면 알을 낳고, 알이 바닥에 떨어지면 병아리가 된다. GUI랑 스레드를 같이 쓴다.
- 감성 채팅: "상대방이 메시지를 입력하고 있습니다"가 뜨는 채팅. 네이트온 느낌이다.
- 웹 채팅: 웹 소켓으로 만드는 익명 채팅방. CSS는 주신다고 했으니 꾸미는 데 시간 쓸 필요는 없다.
- 아기돼지 삼형제, 잠자는 숲속의 공주: 멀티스레드 동기화 실습. 돼지들이 각자 놀다가 집에는 같이 들어와야 하고, 공주는 왕자가 와야 일어난다.
- 짱구네 집: 할머니, 엄마, 짱구 상속 관계로 다형성을 확인하는 복습용 예제다.

## 프로그래밍이랑 SW 개발은 다르다

```text
요구사항 분석 → 구조 설계 → 기능 설계 → 구현 → 테스트 → 문서 작성 → 유지보수, 버전업 (반복)
```

요즘 개발자한테 중요한 건 문법보다 무엇을, 왜, 어떻게 만들지 정하는 과정이라고 하셨다. AI에게 제대로 시키려고 해도 아키텍처를 어느 정도는 알아야 한다고.

그리고 현업에서 혼자 개발하는 사람은 없다. 고객도 있고 매니저도 있고 동료도 있다. 그래서 서너 명이 모여서 이야기하는 연습부터 해보자고 하셨다.

프로그래머가 제일 힘들어하는 일이 뭔지 조사한 자료도 보여주셨는데, 1위가 변수 이름이나 클래스 이름 정하기였고, 주석도 문서도 없는 남의 코드 고치기도 순위에 있었다. 좀 웃기면서도 공감됐다.

## 수업 운영

### 실습이랑 과제

실습은 수업 시간 안에 끝낼 만한 미션이다. 솔루션이 있긴 한데 먼저 내가 해보고 참고하라고 하셨다.

과제는 그 주에 한 걸 복기하고 정리하는 거다. 복기는 교수님께서 돌려준 코드를 보는 게 아니라 내가 혼자 다시 해보는 것. 과제는 솔루션이 없고, 수업 끝나고 두 시간 정도 걸리게 내신다고 했다.

- 제출하면 기본 10점, 잘하면 가산점(+1~+3), 부실하면 감점
- 에러 때문에 하루 종일 붙잡고 있지 말고 빨리 질문하기. AI한테 물어보다가 엉뚱한 데로 새는 경우가 많다고 하셨다.

### 평가

- 중간, 기말 각 30~35%, 실습 20%, 과제 20%, 출석 10%
- 전반부는 중간고사, 후반부는 기말고사 대신 프로젝트
- 결석 2번까지는 인정결석으로 처리해주신다. 보강은 없다.

{: .notice--warning}
마감은 OT 때 토요일 23시라고 하셨는데, 2주차부터 화요일 마감으로 바뀌었다. 1초만 늦어도 다음 날로 처리되니까 미리 올리자.

## 공부 방법

- 이론은 바로 실습해보고, 내 수준에 맞는 lab을 고른다. lab을 전부 할 필요는 없고 필수 하나랑 응용 하나 정도면 된다.
- 주제별로 한 페이지 정리를 하는데 형식은 자유고 기술 블로그를 추천하셨다. 시험 볼 때 내가 정리한 것만 쭉 봐도 머리에 들어오고, 나중에 다른 사람이 봤을 때도 성실하게 공부했다는 게 보인다고. 쓸 때는 딱딱하게 말고 나한테 말하듯이 쓰라고 하셨다.
- 전공이니까 매주 수업 끝나고 두세 시간은 복습하기
- 자바 책은 한 권 이상 꼭 읽기. "입문자를 위한"이라는 제목만 보고 고르지 말고 직접 펼쳐보고 고르기

지난 학기에 AI로 정리해서 오타까지 그대로 옮겨 낸 과제가 있었다는 얘기를 하시면서, AI 결과를 그대로 내지 말라고 몇 번이나 강조하셨다.

## 정리

자프실2는 자프실1을 한 번 더 듣는 수업이 아니라, OOP를 응용하고 백엔드 쪽까지 가보는 수업이다. 알기만 하는 게 아니라 할 줄 알아야 한다는 말을 계속 떠올리면서 들어야겠다.
