## 멀티태스킹, 멀티프로세스, MultiThread

이름이 다 비슷해서 헷갈리는데, 단위가 뭔지를 보면 구분된다.

| | 단위 | 뜻 |
| --- | --- | --- |
| 멀티태스킹 | 작업(task) | 하나의 CPU가 여러 작업을 번갈아 처리 |
| 멀티프로세스 | 프로세스(OS가 관리하는 실행 단위) | 여러 CPU나 코어로 여러 프로세스를 실행 |
| MultiThread | Thread(프로세스 안의 작은 실행 단위) | 한 프로그램 안에서 여러 작업을 동시에 |

### 멀티태스킹

하나의 CPU가 빠르게 작업을 전환해서 동시에 처리하는 것처럼 보이게 하는 것이다.

교수님 비유가 재밌었다. 가수가 노래하고 춤출 때, 만약 번갈아 하지 않는다면 노래 다 끝내고 처음부터 다시 춤을 춰야 한다. 그게 아니라 노래하고 춤추고를 아주 빠르게 반복하니까 동시에 하는 것처럼 보이는 거다.

우리가 음악 틀어놓고 브라우징하면서 다운로드받으면서 공부하는 것도 사실은 뇌가 빠르게 왔다 갔다 하는 거라고 하셨다.

### 멀티프로세스

CPU나 코어를 여러 개 써서 프로세스 여러 개를 동시에 실행한다. 프로세스는 OS가 관리하는 실행 단위다.

- 프로세스끼리는 **메모리를 공유하지 않는다.** 크롬 하나, 워드 하나, PPT 하나를 띄우면 각자 자기 작업 영역이 생긴다
- 서로 독립적이라 안정성이 높다
- 크롬이 탭마다 별도 프로세스를 띄우는 구조가 이거다

### MultiThread

프로세스는 하나인데, 그 안에서 여러 작업(미니 프로세스)을 동시에 수행한다. 이 작은 단위를 Thread라고 부른다.

- Thread끼리는 **메모리와 자원을 공유한다**
- 경량성: 프로세스보다 만들고 없애는 비용이 낮다
- 응답이 빠르다
- 대신 동시에 접근하면서 동기화 문제가 생길 수 있다

교수님께서 여기서 화장실 비유를 드셨다. 집은 하나인데 화장실은 한두 개다. 가족이 5명이어도 사람 수만큼 화장실을 두고 살지는 않는다. 자원을 공유하니까, 아빠가 쓰고 계시는데 문을 활짝 열고 들어가면 안 되는 거다. 카페 화장실처럼 누가 쓰고 있으면 기다리고, 안에서는 잠그고. 이런 처리가 동기화이고, MultiThread의 핵심이라고 하셨다.

우리가 쓰는 웹 서비스도 전부 MultiThread 기반이다. 웹 서버가 홍길동 분신술처럼 클라이언트마다 웹 서비스 Thread를 만들어서 각각 응대해준다. 그래서 "나 저 사람 다음이야" 하고 기다리는 느낌이 안 드는 거다.

게임도 그래픽 렌더링, 사용자 입력 처리, 네트워크 통신을 각각 별도 Thread로 돌린다.

## 동시성과 병렬성

| | 동시성(Concurrency) | 병렬성(Parallelism) |
| --- | --- | --- |
| 구조 | 하나의 CPU가 작업을 쪼개 번갈아 실행 | 여러 CPU가 실제로 동시에 처리 |
| 모양 | Thread1 Thread2 Thread1 Thread2... | Thread1 + Thread2 |
| 자바에서 | Thread, Runnable, synchronized | parallelStream(), ForkJoinPool |

동시성은 일꾼은 하나인데 할 일이 너무 많을 때 조금씩 번갈아 하는 거고, 병렬성은 일꾼이 여러 명이라 진짜로 같이 하는 거다.

병렬성도 코어 수보다 Thread가 많아지면 누가 언제 실행될지 정해줘야 하는데, 그게 스케줄링이고 OS가 한다. 우리가 이번 주에 보는 건 동시성 쪽이다.

## 자바의 MultiThread

자바는 MultiThread를 기본으로 지원한다. C 같은 언어는 Thread 하나 만들려면 많은 노력이 필요한데, 자바는 그냥 만들어 쓰면 되고 따로 환경 설정도 없다.

그리고 놀랐던 것. **우리가 지금까지 쓰던 main이 사실은 Thread였다.** 모든 자바 프로그램은 메인 Thread가 `main()` 메소드를 실행하면서 시작한다. 지금까지는 코드를 위에서 아래로 쭉 실행하고 끝나는 SingleThread 프로그램을 짜고 있었던 거다.

메인 Thread는 작업 Thread들을 만들어서 병렬로 실행시킬 수 있다.

| | 프로세스 종료 조건 |
| --- | --- |
| SingleThread | 메인 Thread가 종료하면 프로세스도 종료 |
| 멀티 Thread | 실행 중인 Thread가 하나라도 있으면 프로세스가 종료되지 않는다 |

메인 Thread가 작업 Thread보다 먼저 끝나도, 작업 Thread가 돌고 있으면 프로그램은 안 끝난다. 작업 Thread들은 서로 독립적이라서 하나가 끝나야 다른 하나가 끝나는 것도 아니다. 다만 "1번이 끝날 때까지 기다렸다가 같이 가자"처럼 제어할 수는 있는데, 그게 `join()`이고 아기돼지 삼형제 실습에서 다룬다고 하셨다.

### 테트리스에는 Thread가 최소 3개

Thread가 왜 필요한지 확 와닿았던 예시다. 테트리스를 만들면 최소 3개의 Thread가 필요하다.

- 오디오 재생
- 블록을 아래로 움직이기
- 키 입력을 받아 블록 방향 바꾸기

Thread를 안 쓰면 블록이 다 떨어질 때까지 키를 못 누른다. JVM은 이 셋 중 하나를 골라 실행하고, 다른 걸 실행하려면 하던 걸 일시 중단하고 넘어간다.

## Thread의 상태

```text
                      interrupt(), notify(), notifyAll()
   [일시 정지]  ←─────────────────────────→  [실행 대기]
   WAITING                                    RUNNABLE
   TIMED_WAITING     sleep(), join(), wait()      ↓ ↑ yield()
   BLOCKED                                      [실행]  ──→ [종료]
```

| 상태 | 열거 상수 | 설명 |
| --- | --- | --- |
| 객체 생성 | `NEW` | 객체는 만들었지만 아직 start()를 안 부른 상태 |
| 실행 준비 | `RUNNABLE` | start()가 호출돼서 실행 가능한 상태. 실제로 실행 중일 수도, CPU를 기다리는 중일 수도 있다 |
| 일시 정지 | `BLOCKED` | 다른 Thread가 가진 락(lock)을 기다리는 중 |
| | `WAITING` | wait()를 호출한 상태. 다른 Thread가 notify 해줄 때까지 무한 대기 |
| | `TIMED_WAITING` | 정해진 시간 동안만 대기. `sleep(ms)`, `join(ms)` |
| 종료 | `TERMINATED` | 실행이 끝난 상태. 정상 종료든 예외든 |

교수님께서 짱구가 놀이터에서 그네 타는 걸로 설명해주셨는데 이걸로 한 번에 이해됐다.

- **생성:** 짱구가 태어났다. 신발 신고 나온다
- **실행 대기(RUNNABLE):** 그네를 타려고 줄을 선다. 줄에 서 있는 순간부터 상태는 RUNNABLE이다. 실제로 그네를 타는 중에도 RUNNABLE이다(그림에 RUNNABLE이 두 군데 있는 게 오타가 아니라고 하셨다)
- **일시 정지:** 짱구가 "나 아이스크림 먹고 올게" 하고 빠지는 게 `sleep()`이다. 쉬는 동안 그네는 다른 애가 타도 된다
- **BLOCKED:** 내가 타려고 줄을 섰는데 앞사람이 안 내려온다. 기다릴 수밖에 없다. 이건 내가 스스로 쉬는 게 아니라 막힌 거다
- **WAITING:** "그네 고장 났으니 대피하세요" 같은 방송이 나온 상황. 고쳐서 알려줄 때까지(`notify()`) 기다린다
- **종료:** 다 타고 "그만할래" 하면 끝

여기서 빨간 별(`sleep()`, `join()`, `wait()`)은 Thread가 자기 자신한테 보내는 신호고, 파란 쪽(`notify()`, `notifyAll()`)은 밖에서 오는 방송 같은 거다.

실행 대기줄은 스택이 아니라 큐(대기 큐)다. 먼저 들어간 게 먼저 나와야 하니까. 다만 내 순서가 됐다고 바로 실행되는 게 아니라, OS 스케줄러가 정하는 대로 실행된다.

`stop()`, `resume()`, `suspend()`는 안전성 문제 때문에 쓰지 않는다. 동작은 하지만 실무에서 쓰면 안 된다고 하셨다.

## 동기화는 왜 필요한가

여러 Thread가 공유 데이터에 동시에 접근하면 예상치 못한 값이 나올 수 있다. 그래서 공유 데이터를 쓰는 Thread들을 한 줄로 세워서, 한 Thread가 작업을 끝낼 때까지 다른 Thread가 기다리게 한다.

자바에서 쓰는 방법은 두 가지다.

- `synchronized`로 동기화 블록(임계 영역) 지정하기. 화장실처럼 한 번에 한 명만
- `wait()`, `notify()`로 실행 순서 제어하기

교수님께서 강아지 밥그릇 그림을 보여주셨다. 개발자의 이상은 강아지들이 각자 자기 밥그릇을 먹는 건데, 현실은 난리가 난 그림이었다. 동기화가 안 되면 이렇게 된다는 뜻이다.

이 부분(MyBank, 가족 공유 계좌, 아기돼지 삼형제)은 연휴 지나고 다음 주에 실습한다. Supplement의 Lab#8~#10(잠자는 숲속의 공주, 생산자와 소비자)은 고학년이나 관심 있는 사람이 보라고 하셔서, 나도 여유가 되면 같이 해보려고 한다.

## 정리

- 멀티태스킹은 작업 단위, 멀티프로세스는 프로세스 단위, MultiThread는 Thread 단위다
- 프로세스끼리는 메모리를 공유하지 않고, Thread끼리는 공유한다. 그래서 가볍지만 동기화 문제가 생긴다
- 동시성은 하나의 CPU가 번갈아, 병렬성은 여러 CPU가 실제로 동시에
- 자바의 main도 Thread다. MultiThread에서는 실행 중인 Thread가 하나라도 있으면 프로세스가 안 끝난다
- 상태는 NEW, RUNNABLE, BLOCKED/WAITING/TIMED_WAITING, TERMINATED. 그네 타는 짱구로 기억하기
- `stop()`, `resume()`, `suspend()`는 쓰지 않는다
